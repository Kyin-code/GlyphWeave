# 真实世界人文聚落形态调研与 GlyphWeave 生成规则

> 版本：v1.0（2026-09-06）
> 范围：6 km × 10 km 现代社会地图；本文件只做研究、归纳和设计，不改动生成代码。
> 目的：把“参考某个国家风格”改为可验证的形态机制，让 Rust Core 生成可解释的聚落、道路、建筑、绿地、水岸和人类地形工程。

## 1. 结论先行

真实世界不是把建筑随机放到道路旁，而是多个历史、地形、制度和交通层叠加的结果。生成器应区分四层：

1. **自然约束**：海岸、河谷、坡度、洪泛区、土壤、地震/滑坡、山脊和视线。
2. **基础设施骨架**：港口、铁路、高速/快速路、桥梁、堤坝、排水和公共交通。
3. **土地制度与历史**：旧城、村庄、宗教地标、工业地块、殖民网格、农田边界、产权粒度。
4. **近期开发**：住宅小区、商场、办公园区、旅游区、夜市、海滨公园和填海新区。

因此国家/地区不应是一个“建筑风格开关”，而应选择一组参数分布：街区尺度、道路层级、地块深度、建筑退界、混合使用、绿地比例、坡地工程、滨水公共性和历史叠加程度。

## 2. 调研方法与资料等级

- A 级：政府规划/设计导则、官方地理数据、法律和城市规划手册。
- B 级：OpenStreetMap/Overpass、公开卫星与街景、城市开放 GIS；适合测量道路、建筑、土地利用和水系，但不能单独推断建筑年代或社会意义。
- C 级：学术论文、城市形态学研究、公开案例研究。
- D 级：旅游网页和图片，仅作观察线索，不作为硬规则。

本次使用的基础资料包括：北京市城市设计导则、纽约 DOT Street Design Manual、香港 HKPSG、日本国土交通省街道设计指南、欧盟 Urban Nature Plans 与城乡联系资料、OpenStreetMap Overpass 文档、Red Blob Games MapGen4 源码与说明。官方资料强调街道、公共空间、滨水开放、绿化和设施的联动，而不是孤立建筑摆放。[1][2][3][4][5][6][7]

## 3. 统一观察字段

每个案例都按以下字段观察，后续可映射到 `MorphologyProfile`：

- 地形/水文；
- 城区、乡村、荒野的空间梯度；
- 主干路、次干路、支路、步行路、铁路、高架/桥梁；
- 建筑类型、层数、体量、退界、朝向和入口关系；
- 公共服务：学校、医院、宗教、市场、商业、工业、公交换乘；
- 绿化：街树、庭院、公园、河岸带、农田林网、自然保育地；
- 人类工程：填海、削坡、挡墙、堤坝、河道硬化/恢复、隧道、架桥；
- 可生成的机制与不确定性。

**中国共性规则**：

- 城市常由“旧核心 + 主干路/轨道 + 新区 + 城中村/村镇 + 生态缓冲”组成，不是单一密度场。
- 河流、湖泊和海岸边应有连续公共通行、绿带或堤防系统；商业和旅游设施集中在可达节点，不应沿整条岸线均匀铺开。
- 山地城市先解决高差：台地、挡墙、梯道、桥梁、隧道和排水先于建筑。
- 乡村不是低密城市；农田、水渠、林带、晒场、宅基地和村口公共空间要共同生成。

**美国共性规则**：

- 高速路、铁路、停车场、工业和低密住宅会形成大尺度断裂，不能用普通小路随机填补。
- 轨道站、大学、医院、体育场、商业中心是“高强度节点”，周围街区可更细、更混合；节点之间通过主干路或公共交通连接。
- 教堂、消防站、学校、社区中心通常位于街区边缘、交叉口或开放空间旁，不完全等同于住宅建筑。
- 海岸/河岸要区分港口工业、公共公园、旅游商业、住宅滨水和湿地保育，不能全部生成同一种 waterfront。

## 9. 跨地区形态规则

### 9.1 相对位置不是固定距离，而是关系图

推荐在 Rust Core 中把关系写成带方向和权重的约束：

- `Building -> Road`: 入口必须连到人行/道路，正面朝向可达边；
- `Building -> Parcel`: 建筑占地、退界、后院和消防间距；
- `Commercial -> TransitNode/MainStreet`: 高概率邻接；
- `School/Church/Civic -> Park/Square/QuietStreet`: 高概率邻接；
- `Industry -> Rail/Arterial/WaterPort`: 高概率邻接，但与住宅设置缓冲；
- `Market/NightMarket -> Transit + MainStreet + PublicSpace`: 需要可扩展的摊位/人流区；
- `Waterfront -> PublicAccess/Levee/Wetland/Port`: 先分类，再决定建筑关系；
- `Vegetation/Rock -> Road/Entrance/Drainage`: 避让净空、排水和维护带。

### 9.2 12 种聚落原型，而不是国家模板

1. 河谷线性镇；2. 海湾港口；3. 山前台地城；4. 平原网格城；5. 轨道站点新城；6. 工业—铁路带；7. 湖滨旅游城；8. 三角洲堤防城；9. 岛屿多中心；10. 林地村镇；11. 农田道路聚落；12. 旧城—新区拼接体。

每个原型只给出参数分布：道路曲率、街区面积、地块粒度、建筑层数、开放空间比例、公共设施间距、工程强度和历史叠加概率。

## 10. 生成顺序建议

```text
自然地形与水文
→ 灾害/保育/洪泛/坡度图
→ 历史不可移动要素与旧路
→ 港口、铁路、高速、桥梁、堤坝、排水等基础设施
→ 城市/乡村/荒野分区与聚落种子
→ 主干路和公共交通节点
→ 街区/地块/公共空间
→ 建筑、入口、围墙、院落
→ 商业、学校、宗教、市政、市场、夜市、旅游设施
→ 街树、农田林带、自然公园、岩石等细节
→ 人类自然相互影响：填海、削坡、挡墙、河道治理、植被恢复、侵蚀
→ 全局审计与修复
```

“现有石头/现有地皮”必须在自然层作为 `ExistingFeature` 先落地，并声明可移动性、保护级别、地基影响和水文影响；后续道路和建筑只能绕行、工程化处理或明确移除，不能在末端随机覆盖。

## 11. 适合 GlyphWeave 的数据合同

```text
MorphologyProfile
  terrain_archetype: valley | coast | delta | plateau | mountain_foot | plain
  settlement_archetype: 12种原型之一
  density_field: 连续或分区目标
  block_area_range_m2
  parcel_frontage_range_m
  road_hierarchy: arterial/collector/local/alley/path
  frontage_policy: detached | street_wall | courtyard | mixed
  height_distribution: 分位数而不是单值
  land_use_mix: 住宅/商业/工业/公共/绿地/农业预算
  public_space_network: 广场/公园/河岸/绿道节点
  infrastructure_edges: rail/highway/bridge/levee/utility
  heritage_anchors: church/temple/old_market/old_road/ruin
  engineering_policy: cut_fill/retaining/embankment/reclamation
  climate_hazard_policy: flood/fire/landslide/storm_surge
```

所有字段都应区分 `hard_constraint`、`soft_preference`、`observed_source`、`inference` 和 `confidence`。Agent 只输出此类高层意图和候选参数；Rust Core 负责几何、拓扑、预算、冲突、路径、地形工程和审计。

## 12. 不能简单编码的内容

建筑立面、夜市氛围、宗教意义、历史年代、社区社会关系和“看起来像某地”不能直接由距离阈值决定。应先生成可解释的空间条件，再由资产合同和 renderer 表现视觉差异。不要用真实城市坐标复制整个场景，也不要把国家标签当作碰撞规则。

## 13. 对当前项目的直接建议

1. 当前 AccessGraph、最终 heightfield、ReservationLayer 和 authored asset contract 是正确方向，应继续扩展为关系图而非更多随机摆放。
2. 将 `urban ratio` 改为分区预算闭环：面积预算、地块预算、建筑基底预算分别审计。
3. 增加 `ExistingFeature` 与 `InfrastructureCorridor` 的持久化合同。
4. 生成报告记录每个对象的“为什么在这里”：父节点、约束、评分、替代候选和拒绝原因。
5. 6×10 km 地图优先生成 3–8 个聚落节点及其城乡过渡，不要试图铺满统一住宅。
6. 把桥、挡墙、堤坝、隧道、梯道和填海地块作为工程实体，而不是 heightfield 的后处理特效。
