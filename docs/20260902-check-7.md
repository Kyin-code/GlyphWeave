- **目标**：修复第 6 次复核发现的 rulesMode fail-open 与 source entity 语义丢失问题。

## 已修改

### 1. rulesMode 改为 fail-closed

`bake_world()` 在 `style.rulesMode == "rules"` 时会预加载 rules directory：

```text
rules directory missing / empty / invalid
    -> WorldgenError::InvalidRules
    -> generate-world exit 1
```

不再允许 `apply_rules_mode()` 在规则加载失败后静默返回 legacy proposed entities。

### 2. 规则重放保留 source entity 语义

新增 `PlacementSource`，并让 `PlacementRequest` 携带：

- `entity_id`；
- `asset_id`；
- `kind`；
- `width_m` / `depth_m` / `height_m`；
- `scale`。

`place_all()` / `place_one_with_source()` 现在：

- 使用 source geometry + descriptor clearance 做 hard constraint 检查；
- 成功时保留 source entity ID、asset、kind、尺寸和 scale；
- 90° rotation 时才交换 source width/depth；
- descriptor 继续只作为约束、tags、phase、priority 和 fallback 的来源。

这避免了此前商业中心、学校和长条道路被强制改写成住宅/8×8 road descriptor geometry 的问题。

### 3. 相对 rulesDir 支持

`glyphweave generate-world MANIFEST OUTPUT` 现在把 manifest 内相对 `style.rulesDir` 按 manifest 所在目录解析，避免 CLI 启动 cwd 改变路径含义。

### 通过

- [x] rulesMode 会调用 `place_all()`。

### 仍未通过 / 需要独立实现

- [ ] rulesMode 的基准 descriptor 仍不足以容纳 commercial_center、school、road strip 等真实 source geometry，因此严格规则模式会剔除许多提案实体。
- [ ] 需要为系统对象和大型公共建筑建立独立 descriptor，或引入 descriptor inheritance / geometry ranges。
- [ ] 生成后 baked world 的自动 audit gate 未接入 `bake_world()`。
- [ ] PlacementRequest 与 OccupancyGrid / reservation / rollback 尚未统一。
- [ ] 规则环境查询尚未完全按 source width/depth/rotation 计算坡度。

## 结论

第 6 次报告中的两个直接阻塞问题已修复：

1. rulesMode 不再静默退回 legacy；
2. rules re-placement 不再丢失 source entity 的 asset/kind/geometry。

但严格规则模式会暴露当前 descriptor 覆盖与参数不足的问题。下一步应优先补齐大型建筑、道路长条和系统对象 descriptor，而不是放宽或绕过 hard constraints。
