# 规则引擎修复复核报告（第 5 次）

## 已完成的本次修复

1. **碰撞判定对称化**
   - 普通实体之间的碰撞由同一策略判断；
   - road/bridge/sidewalk 仍作为交通表面例外，允许与其他对象保持现有“贴边/路旁”语义；
   - 新增 hard→soft 与 soft→hard 双向碰撞单元测试。

2. **`AvoidTag` 变为可声明的 TOML 规则**
   - 新增 `[[relations.avoid_tag]]`（也接受 `avoid_tags`）；
   - loader 校验 tag 和 distance；
   - constraint 编译为 `AvoidTag`；
   - 审计时将匹配 descriptor 的 tags 写入 `PlacedKind`，不再固定为空；
   - reject 能回填冲突实体 ID。

3. **footprint 采样增强**
   - 地面、水体、坡度、biome 和 hazard 检查使用中心、四角和边中点共 9 个采样点；
   - 解决仅检查中心或四角造成的部分漏检。

4. **biome/hazard 拒绝原因与统计拆分**
   - 新增 `ForbiddenBiome` 与带具体值的 `ForbiddenHazard`；
   - 报告新增 `forbidden_biomes`、`forbidden_hazards`、`slope_too_high`、`out_of_bounds`；
   - CLI 多 scene 汇总这些字段。

5. **放置诊断和规则目录健壮性**
   - `place_one()` 在全失败时返回所有候选/旋转尝试的 reject，而不只保留首条；
   - `AvoidKind` 和 audit 的 `conflict_with` 使用实体 ID；
   - loader 仅加载 `*.object.toml`，忽略普通 TOML；
   - registry 检查 descriptor id/kind/applies_to 的重复覆盖；
   - 树对象删除了不存在的 GLB 引用，基准规则目录可通过 `check-assets`。

## 仍未完成的主阻塞

`bevy/crates/core/src/worldgen.rs::generate_entities_with_profile()` 仍使用现有随机/模板生成逻辑，尚未调用 `rules::place_all()`。

因此目前的真实状态是：

```text
现有 worldgen -> 生成实体 -> rules audit（诊断）

place_all -> 可独立调用的规则放置原型
```

而不是：

```text
worldgen -> PlacementRequest -> place_all -> commit entities / occupancy / terrain carve
```

在这个切换完成前，规则不会主动阻止现有生成结果中的违规，只能在生成后报告。

## 下一步建议

1. 在 manifest/style 增加显式 `rulesMode`，先在 demo profile 中启用；
2. 将道路、建筑、功能设施、植被的生成计划转换为 `PlacementRequest`；
3. 将 `place_all()` 输出接入 entities、terrain carve 和统一 occupancy；
4. 保留 legacy generator + audit 作为 A/B 回归通道；
5. 对相同 seed 断言规则模式的违规报告为零或处于允许阈值内。
