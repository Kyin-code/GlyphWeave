## 1. 背景

GlyphWeave 的目标不是为某一个固定测试场景手工摆放建筑，而是提供一个可以被 Agent 反复试生成、修改和验收的通用地图生成器。此前规则引擎已经具备 descriptor、放置顺序、旋转 footprint、baked audit 等能力，但实际 strict 生成仍暴露出几个会直接影响 Agent 可靠性的缺口：

- 建筑在规则放置后，地形 carve 可能改变实体底部与最终地面的关系；
- 道路/人行道的路床和混合环带与规则碰撞 footprint 不一致；
- source 自带 90° 旋转时，placement occupancy 与 audit 使用的世界 footprint 不一致；
- placement 阶段被规则拒绝的候选没有进入正式生成报告，导致“地图变空”无法解释；
- `release` profile 在质量门禁中没有完整复用 strict 的阻断条件。

这些问题不是某个具体城市坐标的问题，而是生成器的空间语义和质量反馈闭环问题，因此本轮优先修复基础逻辑，不扩展具体测试场景。

## 2. 本轮检查方向

### 2.1 生成 profile 与门禁

检查 `legacy / prototype / strict / release` 是否能被 Manifest 表达，strict/release 是否强制使用规则模式，`world-quality-gate` 是否读取最终 baked 规则报告、版本信息和发布资产。

### 2.2 空间语义一致性

检查同一实体的 local width/depth、rotation、clearance、world footprint 是否在以下路径保持一致：

- rules placement；
- occupancy reservation；
- terrain carve；
- baked heightfield；
- rules audit；
- scale audit。

### 2.3 接地与地形

检查建筑、树、灌木、草、岩石等地表实体是否使用 footprint 内最高地面采样；检查道路路床抬升是否会制造浮空或下陷；检查生成填方是否会挖低自然地面。

### 2.4 碰撞与自然物避让

检查道路/人行道与建筑、自然物与道路/建筑、入口走廊与 soft entity 的冲突是否能在数据层被拒绝并写入冲突实体 ID。

### 2.5 Agent 可诊断性

检查规则 placement 被拒候选是否包含 proposed、placed、rejected 和按原因统计，确保 Agent 能区分“规则拒绝”与“生成器没有提出”。

### 3.3 生成实体的最终 baked 接地闭环

新增两层保护：

1. 在生成初始 carve 后，使用 preliminary carved surface 对所有 grounded entity 做两轮接地 reconciliation；
2. 生成 heightfield 后，再使用实际 `baked_samples` 对实体 footprint 重新采样并提升实体底部，避免路床或相邻 pad 造成最终 audit 的浮空误报。

该逻辑不通过把实体埋入海平面来“修复”接地，而是只允许生成填方抬升地表/实体，禁止生成 carve 把较高自然地面挖低。

- [x] sidecar / gemap / world index 基本发布产物链路存在。

### 不作为本轮完成项

以下仍不是完整的 Agent 世界编辑闭环：

1. Patch chain 仍主要支持 landmark 操作，尚未支持 entity/style/scene graph 的完整 add/update/remove、reverse patch、局部重烘焙和任意版本重建；
2. Intent 新字段已经结构化并写入 Manifest，但自然语言 `draft_from_text()` 尚未完整解析地标、道路、硬约束/软偏好，也没有把所有 Intent 直接转成 planner 输入；
3. boundary summary 目前是 chunk 级摘要，尚未完成 scene-to-scene 道路/河流 transition 的配对门禁；
4. asset registry 仍未完全校验真实模型的数值 pivot、bounds、bottom-contact、LOD 和模型 hash；
5. `world-quality-gate` 目前仍会把普通质量 warning 记录为 warning，而不是按不同 profile 建立完整的密度/功能覆盖率阈值；
6. 本轮未进行 HTML/WebGL 视觉验收，2.5D 首屏约 30 秒的问题按此前约定留到后续性能批次。

## 7. 后续建议

下一批应优先做“可量化而非增加更多 fixture”：

1. 把 placement 的 `rejectedCandidates` 与实体实际 `placedItems` 纳入 profile 阈值，避免规则过严导致地图空洞；
2. 将道路连通率、入口可达率、land-use 覆盖率加入 strict/release gate，并对低密度主题使用独立目标；
3. 把 Intent 结构接入统一 planner，保持 Agent 自然语言归化是主链路；
4. 完成 patch chain 的实体/样式/场景操作和局部重烘焙；
5. 完成 `.gemap` + sidecar pack/unpack 与 hash gate；
6. 最后再做 HTML/WebGL 视觉和 30 秒切换性能优化。
