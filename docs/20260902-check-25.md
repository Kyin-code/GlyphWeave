# 20260902 Check 25：树木道路碰撞与建筑/道路下陷复核

## 1. 结论

**问题确认，已修复一批核心错误，可继续测试。**

用户反馈的两个现象并不是单一的“渲染参数问题”：

1. 树木确实会生成到道路 footprint 内；
2. 建筑 foundation 的坐标系使用错误，会把 world 坐标再次叠加到已经位于 world 的建筑组上，造成房屋出现下陷、脱离或基础位置异常；
3. 规则引擎存在，但默认 Manifest 使用的是 `legacy` 模式，且原有生成后过滤没有覆盖 planner 后新增的全部实体，因此不能把规则引擎当作已经全面接管生成。

## 2. 树木为什么会在路上

此前的 worldgen 只在部分早期模板阶段检查树木与建筑的关系，并没有在所有 land-use planner 完成后统一检查树木与道路关系。

尤其是：

```text
template entities
    -> early retain
    -> append_modern_landuse_content / waterfront planner
    -> rules mode（可选）
```

道路和树木会在不同阶段追加，导致后加入的树木绕过早期过滤。

本轮新增最终 clearance pass，在全部规划器完成后统一检查：

- `tree`；
- `bush`；
- `grass_clump`；
- `rock`；
- `fallen_log`。

这些自然对象必须避开：

- `road`；
- `sidewalk`；
- 所有建筑 footprint。

实测修复前的河流城市中，单条道路可检测到 9～10 个树木/自然对象重叠；修复后四条道路均为：

```text
details=0
```

## 3. 房屋/道路为什么会出现奇怪下陷

### 3.1 建筑 foundation 坐标系错误

HTML 建筑 builder 通常先把 group 放到：

```text
(entity.worldX, entity.worldY, entity.worldZ)
```

但旧版 `applySlopeFoundation()` 又把 foundation 放到了：

```text
(entity.worldX, absoluteY, entity.worldZ)
```

这会造成 entity world 坐标被叠加两次：

```text
group world position + foundation world position
```

结果就是：

- foundation 跑到远处；
- 房屋底座与地形不一致；
- 斜坡场景看起来像房屋下陷或悬空。

### 3.2 修复方式

文件：

```text
G:\difyllmwiki\GlyphWeave\adapters\html\render\buildings.js
```

现在 foundation 统一使用 entity-local 坐标：

- `x = 0`；
- `z = 0`；
- `y` 转换为相对于 `entity.worldY` 的 local offset。

这样不论 foundation 是在 builder 内部创建，还是在 app 中创建，都不会重复叠加 world 坐标。

### 3.3 道路规则

道路使用 strip geometry 按 baked heightfield 采样，而不是简单使用单个中心高度。当前道路可以沿地形连续贴合；在已烘焙场景中，scale audit 会检查其中心高度和地面关系。

如果视觉上仍需要“完全水平的城市道路”，下一阶段应调整 worldgen 的 road carve / roadbed 语义，而不是继续在 HTML renderer 中强行压平。

## 4. 规则引擎当前真实状态

当前不是“完全没有规则”，而是分成三层：

### 已有

- 规则 descriptor；
- `place_all()`；
- 水体、坡度、地面、入口、碰撞、biome/hazard 检查；
- `rulesMode = rules` 时接入放置流程；
- baked `audit_scene`；
- 最终 worldgen 硬安全过滤；
- 本轮新增 planner 完成后的自然对象 clearance。

### 当前默认行为

多数 Manifest 没有明确写：

```json
"rulesMode": "rules"
```

因此默认仍是：

```text
rulesMode = legacy
```

这意味着默认生成主要依赖：

- 生成器候选位置；
- worldgen 最终过滤；
- baked audit 报告。

它不是全量由 `place_all()` 主导的严格放置模式。

### 当前本轮补强

即便是 legacy 模式，也会对道路、建筑和自然对象执行最后一层硬安全过滤，避免明显穿插进入最终 world。

这层过滤不是 rules engine 的替代品，而是 renderer/worldgen 共享的最低安全线。
