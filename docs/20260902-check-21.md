# 20260902 Check 21：通用意图规划与 Agent 入口验收

## 1. 验收结论

**结论：通过，可交给测试。**

本轮没有为深圳湾、内蒙古、西湖等测试样例添加专用分支，而是把已确认的 `generationIntent` 接入通用生成路径：

- `city/town + river/lake`：根据 `WaterGeometry` 和场景边界推导岸线核心、道路、公共建筑与住宅；
- `pastoral`：生成可复用的农田/牧场、水井和住宅组合，并执行边界与建筑占用检查；
- `wilderness`：只生成自然对象，不生成道路和城市建筑；
- 没有 `generationIntent` 的旧 Manifest：保留原有生成行为，避免破坏既有基线。

渲染仍不是本轮阻塞项；验收重点是 Manifest → 意图归一化 → 通用生成 → baked world → 质量/尺度检查链路。

## 2. 本轮检查方向

### 2.1 通用性

- 检查生成器是否只依赖 `generationIntent`、`WaterGeometry`、`LandUseProfile` 和场景尺寸；
- 检查是否没有出现具体地点名称、固定测试坐标或样例专用 if/else；
- 检查旧 Manifest 没有意图时是否维持兼容行为。

### 2.2 Agent 自然语言归一化

- 检查 `intent draft/validate/compile` CLI 是否在帮助文本中可发现；
- 检查中文名称、seed、城市/城镇/牧场/荒野等意图识别；
- 检查 `2km x 1.6km` 等小数公制尺寸是否正确归一化为 `2000m x 1600m`；
- 检查缺少名称、seed 或尺寸时是否失败，而不是静默猜测。

### 2.3 水体定居生成

- 检查河流/湖泊场景的核心位置是否从 `WaterGeometry` 推导；
- 检查普通建筑是否不会沿用旧水体模板的重复建筑填充；
- 检查核心、学校、绿地、住宅等实体是否保持在场景边界外侧并避开水面；
- 检查道路方向和实体 ID 是否稳定、可审计。

### 2.4 农牧与荒野生成

- pastoral 是否至少产生 `pasture`、`farmland` 和 `residential_home`；
- pastoral 生成的井、住宅是否经过边界和建筑占用检查；
- wilderness 是否没有道路和城市建筑；
- 相同 seed 是否保持确定性。

### 2.5 质量报告与资产契约

- `compile_manifest` 是否携带默认 `assetContracts`；
- 水体契约是否包含 `shoreProfile`、`waveModel`；
- 默认资产契约是否覆盖本轮水体细节实体、桥、建筑簇、度假屋、店面等；
- `quality-report` 不应把“有显式定居规划器的结构化水体”误报为 profile 未应用；
- `scale-audit` 应能闭环通过。

## 3. 修改内容

### 3.1 `bevy/crates/core/src/worldgen.rs`

- 修复通用意图规划器之前遗留的 Rust cast 比较语法和 `f64` 参数错误；

  - `wilderness` → 自然内容；
  - `pastoral` → 通用农牧内容；

  - `city/town` + 水体 → 通用岸线定居规划器；
- 对显式水体定居场景移除仅由旧模板生成的普通建筑填充，保留 authored/GIS landmark、水体和交通基础设施；
- 新增边界、水面、建筑占用检查；
- 扩展默认资产契约，覆盖水体细节和通用规划器产生的实体类型；
- 新增显式意图的城市/农牧/荒野测试。

### 3.2 `bevy/crates/core/src/intent.rs`

- 尺寸解析支持小数公制 token，例如 `1.6km`；
- 解析结果按米归一化并进行有限值、正数和 `u32` 范围检查；
- 编译出的 Manifest 自动携带默认 `assetContracts`；
- 结构化水体自动携带 `shoreProfile` 和 `waveModel`；
- 新增小数尺寸回归测试。

### 3.3 `bevy/crates/cli/src/main.rs`

- `--help` 增加：
  - `intent draft INPUT.txt OUTPUT.json`；
  - `intent validate INTENT.json`；
  - `intent compile INTENT.json MANIFEST.json`；
- `quality-report` 正确识别显式水体定居规划器，并仅在可比较的 profile 场景中检查比例目标。

## 6. 当前仍需明确的非阻塞项

1. **渲染视觉验收**：本轮只确认生成数据、baked 高度场、质量和尺度链路；需要渲染端稳定后再做截图评审。
2. **自然语言覆盖面**：当前归一化器是可审计的确定性入口，不是完整 LLM。更复杂的同义表达仍应由 Agent 先转成确认后的 `WorldIntent`，再进入 compile。
3. **profile 比例语义**：结构化水体定居规划器目前使用 profile 的 urban target 影响密度，水面占比和岸线空间不会被错误地当成普通陆地比例进行比较。
4. **完整生成编排**：规则模式已有 `place_all`，后续仍可把更多实体类型完全迁移到 phase/priority 编排；这不阻塞本轮 intent-to-world 链路测试。

## 7. 测试建议

测试人员可以先使用 `work/check-21` 中的输入，随后替换为其他不含地点专名的文本，例如：

- `名称：通用湖畔城镇，seed=12，1.5km x 1.2km 的湖泊城镇`；
- `名称：通用草原牧区，seed=13，3km x 2km 的草原牧场`；
- `名称：通用荒野，seed=14，2km x 2km 的自然保护区`。

验收时重点观察：

- 是否只需要改变文本中的意图和尺寸，就能得到不同但确定性的地图；
- 是否能从报告中追溯 Manifest、scene、entity 和 asset contract；
- 是否不会因为缺少尺寸/seed/名称而生成一个“看似成功但语义错误”的世界。
