# check-33：2.5D 近景加载稳定性复核

> 检查日期：2026-09-04
> 当前结论：**通过（静态 2.5D 加载/稳定性范围）**。本次只验收预览加载、2.5D 不闪退、静态模式和桥体可见性，不扩展到素材比例或完整世界质量门禁。

## 1. 背景

用户反馈 `http://127.0.0.1:8778/preview/index.html` 切换 2.5D 后等待一段时间会闪退。项目当前又明确要求暂时停用风场，优先保证静态画面可用于检查桥、道路、建筑和遮挡。

本次检查发现两类问题：

1. 8778 原服务实际指向旧的 `html-recheck7-20260903` 产物，不是最新深圳湾精简版；
2. 最新源码中静态预览仍会默认加载后处理，并且静态相机的 `OrbitControls.update()` 触发 `change`，`change` 又调用渲染函数，形成递归，最终报 `Maximum call stack size exceeded`。

## 2. 本次修改

### 2.1 静态模式不再默认加载后处理

文件：

- `G:\difyllmwiki\GlyphWeave\adapters\html\app.js`

变更：

- `STATIC_PREVIEW` 保持为 `true`；
- 后处理改为显式 `?fx=1` 才加载；
- 静态模式关闭抗锯齿、阴影和高像素比，减少首帧显存/内存峰值；
- `?nofx` 仍然兼容。

### 2.2 静态 2.5D 默认只加载焦点 chunk

变更：

- 静态近景默认只渲染当前焦点 chunk；
- 只有显式 `?ring=1`，或 skyline 模式，才启用 3×3 chunk 环；
- 草实例预算同步下调；
- 保留 chunk 环压力测试入口，不对通用 worldgen 做场景特判。

这样做的原因是：2.5D 首帧同时创建 1m 地形、PBR 纹理、草实例和实体几何，3×3 环会把初始化峰值放大；静态预览的首要目标是可靠查看一个区域，而不是一次性加载整张世界。

### 2.3 修复静态渲染递归

变更：

- 增加 `renderNearFrame()` 静态渲染入口；
- 静态模式不再在该入口调用 `nearControls.update()`；
- `OrbitControls` 的 `change` 事件只更新信息并请求一次渲染；
- 给重复进入 near 模式增加构建 token，避免旧的异步构建覆盖新画面；
- 增加 `webglcontextlost` 提示，发生 GPU 上下文回收时不再表现为无提示黑屏。

### 2.4 同步最新预览产物和服务根目录

当前 8778 服务根目录：

```text
G:\difyllmwiki\GlyphWeave\bevy\work\shenzhen-bay-minimal-20260904-c
```

访问入口：

```text
http://127.0.0.1:8778/preview/index.html?view=near
```

服务同时提供 `/world.json`、`/scenes/...` 和 `/preview/...`，避免把根目录错误指向 `.../preview` 后再次拼接 `/preview`。
