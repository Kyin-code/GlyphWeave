  - `reed`

连同上一轮的 `civic.object.toml`，规则目录目前通过校验的 descriptor 数量为 **10**。

`lake`、`river` 等水体主体仍作为系统实体透传，不强行套用陆地对象规则；水体的水面/水域约束由 worldgen 的 WaterGeometry 查询负责。

### 1.2 坡度查询改为 footprint-aware

`PlacementContext` 新增可选的 footprint slope query：

```text
(x, z, half_width, half_depth) -> slope
```

规则验证优先使用候选实体实际 footprint 的 half extents；没有专用查询时才回退到 9 点采样和旧的 `slope_at`。

因此大型建筑、长条道路、90° 旋转对象不再全部使用固定 `8×8` 坡度窗口。

新增测试：

- `footprint_slope_uses_actual_candidate_extents`

### 1.3 增加规则侧 PlacementIndex 与 checkpoint rollback

新增 `rules::PlacementIndex`：

- 统一保存规则放置阶段使用的 `PlacedKind` 占用记录；
- `place_all()` 改用该索引；
- 支持 `checkpoint()` / `rollback()`；
- 对外保留旧的 `place_one(..., &mut Vec<PlacedKind>, ...)` 兼容入口；
- 规则候选失败时不会留下 speculative occupancy。

新增测试：

- `placement_index_checkpoint_rolls_back_speculative_entries`

说明：这已经统一了规则 placement 内部的占用记录，但 worldgen legacy 路径的私有 10m `OccupancyGrid` 仍未完全替换为同一个索引；这是下一阶段的结构性改造项。

### 1.4 增加多 seed 确定性回归

新增 worldgen 测试：

- `rules_mode_is_deterministic_across_seed_set`

覆盖 seeds：

```text
1、42、99、20260902
```

验证内容：

- 相同 seed 输出实体 JSON 完全一致；
- entity ID 不重复。

## 4. 当前结论

本轮进一步完成了渲染无关的规则工作：对象覆盖、按真实 footprint 的坡度查询、规则侧占用索引回滚、多 seed 确定性测试，以及 baked-world 最终审计 gate。

当前状态可验收为：

> **规则生成逻辑 v1 基本闭环，具备可运行的规则模式和最终 baked 审计。**

仍不能宣称所有空间一致性已经完成，主要原因是：

1. legacy worldgen 的 10m `OccupancyGrid` 尚未与规则侧 `PlacementIndex` 合并；
2. rollback 尚未覆盖 terrain carve 与实体写入的跨阶段事务；
3. 精确几何、pivot/路床高度和跨 world golden 回归仍缺失；
4. 水体主体属于系统对象，不在 object descriptor 覆盖统计中。
