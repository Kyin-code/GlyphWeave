## 1. 本轮完成的修改

### 1.1 worldgen 与 rules 共用 PlacementIndex

原先 worldgen legacy 路径使用私有 10m bitmask，而 rules placement 使用 `Vec<PlacedKind`。本轮将 worldgen 的 `OccupancyGrid` 改为内部持有规则侧 `PlacementIndex`：

- legacy 提案和 rules placement 使用同一套 footprint 记录结构；
- legacy 仍保留 hard/soft 的简化策略；
- 碰撞判断改为基于已登记 footprint 的 AABB 相交，而不是仅依赖 10m 网格单元；
- 解决对象坐标带 scene origin 时粗网格索引容易失真的问题。

### 1.2 规则侧 checkpoint/rollback

`PlacementIndex` 已提供：

- `checkpoint()`；
- `rollback()`；
- `push()`；
- `as_slice()`；
- `into_entries()`。

`place_all()` 使用统一 index，兼容入口 `place_one()` 仍保持原有 `Vec<PlacedKind>` API。

### 1.3 footprint-aware 坡度

`PlacementContext` 新增：

```text
slope_at_footprint(x, z, half_width, half_depth)
```

放置和审计优先使用候选实体真实 footprint 的 half extents，包括 source scale 和 90° rotation 后的尺寸；没有提供该查询时才回退到旧的 `slope_at`/9 点采样逻辑。

### 1.4 规则 descriptor 覆盖补齐

当前规则目录已经覆盖主要生成对象：

- 普通建筑与 civic 建筑；
- 道路、道路变体、桥、causeway、人行道、渠道；
- 井、路灯、路牌、灯、长椅、公交站、摊位；
- 农田、牧场、林地、自然保护区、灌木、草丛、倒木；
- 芦苇等水边细节；
- 树、石头、沿街商铺。

规则目录当前通过校验的 descriptor 数量为 **10**。

### 1.5 多 seed 确定性回归

新增测试 `rules_mode_is_deterministic_across_seed_set`，覆盖：

```text
1、42、99、20260902
```

验证相同 seed 的实体 JSON 完全一致、entity ID 不重复。

## 4. 不通过项及修改方向

### 4.1 跨阶段事务未完成

**原因**：PlacementIndex 目前只管理实体 footprint，terrain carve 和 scene 文件写入仍在 `bake_world()` 后续阶段执行。

**风险**：如果未来在 carve 或写文件阶段失败，实体 placement 已经计算完成但没有统一 rollback 协议。

**建议**：下一步引入 `WorldBakeTransaction`，至少包含：

1. entity placement snapshot；
2. terrain carve plan；
3. chunk write staging；
4. commit/abort；
5. 失败时清理已写入的 scene 临时文件。

### 4.2 精确几何未完成

**原因**：当前 validator 使用旋转后的 AABB，适合 MVP 验证但无法表达斜向道路、复杂建筑 mesh 和圆形树冠。

**建议**：在渲染资产尺寸契约稳定后，再将 `Footprint` 抽象为 AABB/OBB/Circle/Polygon，避免在资产未定时反复改 schema。

### 4.3 pivot/路床契约未完成

**原因**：`pivot` 已能读取，但 `EntityInstance.world_y`、模型底部、道路抬升路床还没有共享统一的高度基准。

**建议**：建立 `GroundingSpec`，明确：

- pivot 类型；
- object bottom offset；
- roadbed offset；
- carve height source；
- baked audit height source。

### 4.4 golden 回归未完成

**原因**：目前已有多 seed 确定性单元测试，但还没有把完整生成结果保存成可审查的 golden JSON，并设置覆盖率/实体数量阈值。

**建议**：渲染接入前建立 4～8 个 seed 的 `generation-report.json` 基线，锁定：

- checked/passed/rejected；
- unruled 数量；
- 道路/建筑/设施/植被数量；
- land-use area ratio；
- terrain chunk hash。
