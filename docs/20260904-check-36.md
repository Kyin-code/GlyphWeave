# 2026-09-04 HTML 五项视觉修复验收（check-36）

## 1. 背景

check-35 的结论是：当前数据和规则链路已经能运行，但 HTML 视觉层仍停留在功能验证级。主要问题为：桥体可读性不足、默认 2.5D 镜头锁在桥中央、地形在画面中像平面、核心建筑/山体/海岸设施过于像占位几何、草地代码虽已接入但肉眼不可见。

本轮按 check-35 的建议，优先完成五项通用渲染改造：

1. 桥体结构与水面层次；
2. 默认 2.5D 构图；
3. 连续地形与地表视觉；
4. 核心建筑/山体/海岸素材识别度；
5. 草地覆盖和静态可见性。

深圳湾仍只是测试 Manifest，不使用深圳湾坐标特判来替代通用渲染逻辑。

## 3. 完成内容

### 3.1 桥体

- 提高桥面、桁架、桥墩和桥塔的材质区分度；
- 增加桥面厚度与护栏对比；
- 保留桥体完整结构、桥墩、桥塔和桥头坡道；
- 静态预览中关闭动态水面贴图，避免透明水面将桥体压成黑色横带；
- 水面使用稳定的静态颜色，避免集成显卡上出现黑色条纹和桥体吞没。

判定：**通过（结构可见，静态预览稳定）**。

### 3.2 默认 2.5D 镜头

- 默认 harbour 视角不再直接锁定桥体中央；
- 默认视角改为斜向观察，让水面、桥、岸线和远岸地形进入同一画面；
- `?view=bridgehead` 仍保留为专用桥头检查入口；
- `?view=skyline` 保留为全景检查入口，但不作为默认体验。

判定：**条件通过**。默认画面已能同时看到桥、水域、岸线和山体，但场景仍偏空旷，后续需要更丰富的城市轮廓与更合理的视距。

### 3.3 地形与水面

- 继续使用 baked heightfield 作为唯一地形几何来源；
- 保留 normal/roughness 由高度和语义栅格生成的 PBR 路径；
- 含水 chunk 的静态水面不再叠加动态水面纹理和自定义 ripple shader；
- 避免把水面误渲染成黑色条纹平面。

判定：**条件通过**。水面颜色和桥水关系已恢复可读，但目前地形形体的起伏仍主要依赖 baked heightfield，测试场景本身的大面积水域会让陆地起伏显得不足。

### 3.4 核心程序素材

`makeCoastalFeature()` 已从单一 Box/Cone/Sphere 占位组合升级为实体局部结构：

- mountain/rock_mountain：裙座、多个山脊、岩层台阶；
- hill：底座、主体山包、不对称肩部；
- shopping_mall：裙房、玻璃中庭、两翼、入口、屋顶；
- office_tower：裙房、玻璃主体、角部立柱、楼层分隔、冠部；
- convenience_store：门面、橱窗、招牌带、前场；
- boardwalk：木板、横梁、边缘护栏和立柱；
- scenic_belt：树干、树冠和连续基座；
- mudflat：潮沟和泥滩颗粒；
- night_market：摊位、顶棚、支柱和灯带；
- community_plaza：铺装网格、绿岛、座椅和标识构件；
- fence/guardrail：立柱、双层横杆和网面/护栏结构。

所有这些对象仍是轻量程序几何，不宣称已经替代高质量 GLTF/OBJ 美术资产。

判定：**条件通过**。结构识别度比 check-35 有明显提升，但仍属于 stylized blockout，不是最终展示级素材。

### 3.5 草地

- 降低草层生成门槛；
- 增加默认焦点和远景覆盖半径；
- 增加静态草叶高度和宽度；
- 增强根部亮度和整体对比度；
- 提高绿地底色与草叶层的色差；
- 继续通过 `wetness / slope / disturbance / surface` 语义过滤；
- 静态模式的风场参数保持为 0，不重新引入动画风。

判定：**条件通过**。草叶已经能在截图中表现为大量可见细小植被标记，但在 1400m × 2200m 的全景中仍然不会形成近景草甸效果；需使用近景焦点或后续引入专门的连续草簇资产，才能达到 MC 级别的视觉密度。

## 4. 统一视觉合同

本轮没有新建独立 TypeScript/JSON schema，但将新增程序素材的最终分发统一为实体局部几何 + 统一 world transform，并在 `makeCoastalFeature()` 写入：

```text
kind
renderClass
widthM
heightM
depthM
rotationYDeg
pivot
collisionClass
```

landmark 和 entity 均经过同一个 `makeCoastalFeature()`，避免针对深圳湾场景复制 renderer。

判定：**条件通过**。程序素材已经有最小合同，但 OBJ/GLTF 原型、桥体、树木实例和 landmark 特殊 renderer 仍未全部收敛到同一 `EntityVisualContract`，这是后续独立工作项。

## 8. 尚未解决的问题

1. 当前素材仍然是轻量程序几何和少量通用 OBJ/GLTF，离展示级资产还有明显差距；
2. 默认场景仍有大片空旷区域，建筑群和岸线景观的层次不足；
3. 草地在全景视角中仍偏细碎，需要专门的近景草簇、地表覆盖或实例预算策略；
4. 山体已经不再是单一圆锥，但仍未与 baked terrain 高度场完全融合；
5. 含水 chunk 为避免黑色遮挡使用静态水材质，动态水面 PBR 仍应单独做成可选渲染路径；
6. OBJ/GLTF、procedural feature、bridge、vegetation 尚未完全统一到一个资产 registry 驱动的视觉合同。

## 9. 本轮结论

本轮完成了五项针对性修复，解决的是“素材完全像占位块、桥水关系不清、默认镜头不对、草地几乎不可见”的第一层问题。

但验收不能写成“素材质量已经完成”。当前结果更准确的定义是：

> 已从纯调试画面提升为可继续测试的 stylized blockout；规则、位置和渲染分发可以继续验证，但仍不应当作为最终美术展示版本。
