## 1. 本次实际修改

### 1.1 descriptor 适用范围改为显式声明

修改 `ObjectDescriptor::matches_kind()` 与规则目录冲突检查：

- `kind = "building"` 不再自动声明自己适用于实体 kind `building`；
- 只有 `id` 或显式 `applies_to` 才能取得实体 kind 的所有权；
- 避免通用建筑规则与商业中心/学校等专用规则发生隐式抢占；
- 基准 `road`、`tree`、`rock`、`storefront`、普通建筑 descriptor 已补齐显式 canonical alias。

新增：

- `assets/objects/civic.object.toml`

该 descriptor 覆盖：`commercial_center`、`entertainment_center`、`school`、`town_hall`、`market`、`industrial`、`temple`、`church`、`parking_lot`、`green_space`，不再把大型建筑套用住宅规则。

### 1.2 source geometry 与运行时 kind 保持一致

`PlacementRequest` 的 `PlacementSource` 继续保留：

- `entity_id`；
- `asset_id`；
- 原始 `kind`；
- `width_m` / `depth_m` / `height_m`；
- `scale`。

本轮补充修正：

- footprint 碰撞按 `source geometry × scale` 计算；
- 旋转只交换 width/depth；
- 提交到占用索引时使用 source 的运行时 kind，而不是 descriptor 的分类 kind；
- 规则 descriptor 只提供约束、tags、phase、priority、fallback，不覆盖渲染资产和源对象尺寸。

### 1.3 rulesMode fail-closed 与 baked audit gate

- `bake_world()` 在 `rulesMode = "rules"` 时预加载规则目录；缺失、空目录、解析失败均返回 `InvalidRules`；
- `apply_rules_mode()` 内部不再静默回退 legacy；
- terrain chunks 烘焙完成后，使用实际 baked heightfield 对最终实体再次执行 `audit_scene()`；
- 规则模式输出 `rules-audit.json`；
- 若已覆盖实体存在 rejected，生成返回 `RulesAuditFailed`，不再把未通过的 world 当作成功产物；
- 生成阶段发现实体中心没有 baked height sample 时明确失败。

## 4. 对 final-notes 原结论的判定

原文中“rulesMode 已接入 `place_all()`、审计链路和基础规则功能”的描述是正确的；原文把剩余问题全部归为非阻塞打磨则不准确。

本次修改后可以把当前状态表述为：

> **规则审计 + rulesMode 主导生成 + baked 最终审计 gate 已完成。**
>
> 规则引擎 v1 的核心链路可验收，但“完整覆盖现代社会对象、统一占用事务、精确几何与多 seed 回归”仍未完成，不能宣称全部规则能力已经闭环。

后续优先级建议：

1. 为 sidewalk/设施/农田/牧场/自然保护区等 proposal 增加 descriptor，或者明确配置 `unruled` 白名单；
2. 把 `OccupancyGrid`、reservation、rollback、terrain-carve 合并为单一 placement transaction；
3. 将 slope 查询改为 source footprint + rotation 感知；
4. 增加多 seed JSON golden/阈值回归；
5. 最后再实现 OBB/精确 shape，避免在规则覆盖率尚未完整时过早优化几何层。

## 5. 本次验收结论

**结论：部分通过（核心链路通过，完整对象覆盖与事务一致性未通过）。**

可以合并本轮代码作为规则引擎 v1 的试运行基线，但不能以“所有剩余项已全部补齐”作为验收描述。
