# GlyphWeave 大世界生成闭环任务清单

## 目标

将 GlyphWeave 从 ASCII Roguelike 地图编辑器扩展为独立的世界生成与预览
管线。核心内容脱离 Godot，由 Rust Core/CLI 负责；HTML 和 Godot 只是
读取同一份世界数据的适配器。

第一阶段必须完成一个可验证的完整闭环：

```text
自然语言/JSON
    -> glyphweave.manifest.json
    -> Rust CLI 完整烘焙
    -> gemap v3 + sidecar + HTML 预览数据
    -> HTML 分片预览 / Godot 4.7 环境浏览
```

## 已确认的产品约束

- [ ] 默认输出模式为 `2.5d`。
- [ ] 可选输出模式为 `2d`。
- [ ] 当前不实现对外的完整 `3d` 生成模式。
- [ ] 2.5D 采用类似 RTS 的斜俯视环境浏览体验，不实现单位、战斗、建造和 AI。
- [ ] 1m x 1m 是逻辑地图单元，类似 Minecraft 的标准方格坐标。
- [ ] 默认使用 Heightfield + 地表层 + 少量地下体素，而不是所有地形都用体素。
- [ ] 默认地形合并为 Mesh；可切换为 1m³ 方块化视觉表现。
- [ ] 单个场景最小尺寸为 512m x 512m。
- [ ] 单个场景默认尺寸为 1km x 1km。
- [ ] 单个场景最大尺寸为 6km x 10km。
- [ ] 尺寸限制按每个场景独立计算。
- [ ] 场景尺寸允许任意整数米，不要求是 512m 的整数倍。
- [ ] 边缘分块按 512m 存储，超出实际场景范围的区域标记为 `void`。
- [ ] 一个游戏默认允许 1 个场景，可扩展到 3~5 个场景。
- [ ] 超过 5 个场景时只给出资源预算警告，不强制失败。
- [ ] 正式生成必须完整烘焙所有场景和所有分块，不能只生成局部地图。
- [ ] 生成过程可按主地形、主结构、关键地标、普通细节的优先级执行。
- [ ] HTML 和 Godot 只分片加载已烘焙数据，不在运行时临时生成地形。

## 坐标与分块

- [ ] 对外坐标统一使用命名字段 `world_x`、`world_z`、`world_y`。
- [ ] `world_x` 为东西方向，向东为正。
- [ ] `world_z` 为南北方向，向南为正。
- [ ] `world_y` 为高度，单位为米。
- [ ] 对外坐标必须使用 Godot 直观的 X/Z/Y 语义，不允许裸写无说明的三元组。
- [ ] `.gemap v3` 内部继续保持冻结的 `(z, x, y)` 协议序。
- [ ] Rust Core/CLI 负责 X/Z/Y 与 gemap `(z,x,y)` 的显式转换。
- [ ] 转换必须覆盖正坐标、负坐标和所有分块边界，并有单元测试。
- [ ] 流式分块默认尺寸为 512m x 512m。
- [ ] 一个 512m 流式分块可包含多个 `.gemap v3` 的 16m 存储 Chunk。
- [ ] 上游 `.gemap v3` 的 32 x 32 Region 继续作为存储层概念。
- [ ] 必须区分 Streaming Chunk、Storage Chunk 和 Region，禁止混用名称。
- [ ] 所有世界、场景、分块、实体和传送点都必须能反查到完整坐标。

## Manifest 与用户意图

- [ ] 自然语言输入和严格 JSON/YAML 输入都必须支持。
- [ ] 两种输入最终都归一化为唯一的 `glyphweave.manifest.json`。
- [ ] 用户确认 Manifest 后，Rust CLI 才开始正式生成。
- [ ] Seed + Manifest 必须完全可复现。
- [ ] 同一 Seed、Manifest 和生成器版本必须得到一致结果。
- [ ] 手工或 Agent 修改不得直接覆盖原始 Manifest。
- [ ] 每次修改必须追加不可变 Patch。
- [ ] 世界版本由 Manifest 哈希、Patch 链哈希和生成器版本共同确定。
- [ ] 任何关键字段缺失时必须先向用户追问，禁止静默补写用户意图。
- [ ] 软约束可以降级，但必须写入生成报告。
- [ ] 硬约束冲突必须失败，不得静默移动地标、缩小实体或改变场景尺寸。

## 风格与参考素材

- [ ] 风格由用户决定，Skill 不得擅自把类比游戏转换成最终风格。
- [ ] 用户可以用自然语言描述风格。
- [ ] 用户可以直接提供结构化风格参数。
- [ ] 用户可以提供概念图、草图、照片和文字设定作为参考素材。
- [ ] 参考素材只能用于理解和确认方向，不能自动视为正式游戏资源。
- [ ] 风格草案必须经过用户确认后才能写入 Manifest 并生成。
- [ ] 参考游戏名只能作为沟通类比，不得直接复制商业游戏资产或专有视觉元素。
- [ ] 默认占位资源使用原创程序化低多边形/简单几何表现。
- [ ] 生成器必须保留稳定的语义资源槽位，以便后续替换正式资源。

## 关键世界实体与地标

- [ ] 大型人造物、城市、设施和剧情地标必须是 Manifest 一等公民。
- [ ] 关键实体至少需要 ID、名称、类型、用途、完整描述、尺寸、位置和风格。
- [ ] 关键实体缺少必要字段时必须暂停并追问。
- [ ] 每个关键实体使用唯一的全局 `entity_id`。
- [ ] 大型实体使用 anchor、朝向、尺寸和 bounds 定义空间范围。
- [ ] 大型实体允许跨越多个 512m 分块。
- [ ] 跨分块实体只能有一个实体定义，禁止每个分块重复生成完整实体。
- [ ] 分块只保存实体引用、局部可见代理和裁剪信息。
- [ ] 入口、交互点、碰撞、传送点使用全局坐标。
- [ ] 资源只引用 `asset_id`，不将地图数据绑定到具体模型文件。

## 资源替换

- [ ] 生成器不得覆盖用户的 `assets/` 目录。
- [ ] 生成内容统一放入 `generated/`。
- [ ] 用户参考素材放入 `references/`。
- [ ] 用户正式素材放入 `assets/`。
- [ ] 3D 模型优先支持 `.glb`，同时支持 `.gltf + .bin + textures`。
- [ ] Godot 完整资源支持 `.tscn` 和 `.tres`。
- [ ] 2D 纹理支持 `.png` 和 `.webp`。
- [ ] 正式素材必须登记 `asset_id`、格式、单位、原点、朝向、缩放和碰撞规则。
- [ ] `assets/glyphweave.registry.json` 支持按 `asset_id` 覆盖默认占位资源。
- [ ] 替换正式资源时不得修改地图坐标、实体 ID 或玩法数据。

## 场景关系与边界

- [ ] 多场景使用显式 `scene_graph` 管理。
- [ ] 每个场景拥有独立的 scene_id、尺寸、原点、Seed 和分块索引。
- [ ] 场景之间通过道路出口、渡口、山口、洞穴口、传送门等 transition 连接。
- [ ] transition 必须包含源/目标场景、坐标、朝向和目标落点。
- [ ] 相邻场景只有在 Manifest 声明后才执行连续地形生成。
- [ ] 相邻场景边界必须支持高度、河流、道路和地表材质连续性校验。
- [ ] 基础噪声使用世界 Seed、场景 ID 和全局坐标，不依赖生成顺序。
- [ ] 分块可以并行生成，但必须读取相邻边界摘要并执行约束校验。
- [ ] 边界摘要至少包含边缘高度、地形类型、道路/河流出口和连接方向。
- [ ] 无法满足边界约束时必须报告冲突并终止发布版本生成。

## 存储与 LOD

- [ ] `.gemap v3` 作为完整发布归档、交换和离线导入格式。
- [ ] sidecar 作为 HTML 和 Godot 的分片读取格式。
- [ ] sidecar 使用 JSON 元数据 + 二进制主体。
- [ ] `world.json` 保存世界范围、场景图、LOD、Seed、版本和哈希。
- [ ] `scene.json` 保存场景尺寸、原点、分块索引和地标索引。
- [ ] 分块 JSON 保存坐标、有效尺寸、边界摘要、文件名和数据哈希。
- [ ] 高度场使用二进制数组保存，并保留 0.25m 高度精度。
- [ ] 地表材质和通行属性使用压缩二进制数组保存。
- [ ] LOD 0 保存完整 1m 数据，仅在近景分块加载。
- [ ] LOD 1 保存 4m 或 8m 聚合数据，用于中距离预览。
- [ ] LOD 2 保存 32m 或 64m 缩略数据，用于战略地图。
- [ ] 原始 Manifest + Seed 是所有 LOD 的唯一真源。
- [ ] Patch 应按影响范围重建相关分块和低精度缓存。
- [ ] 发布前必须验证 `.gemap v3` 与 sidecar 内容一致。

## Rust Core 与 CLI

- [ ] 复用上游 `glyphweave-core` 的坐标、体素、Region、Chunk 和 codec 能力。
- [ ] 保持 Core 无 Bevy 依赖。
- [ ] 新增世界 Manifest 数据模型和 schema 校验。
- [ ] 新增世界、场景、流式分块和实体索引模型。
- [ ] 新增确定性 Heightfield 生成器。
- [ ] 新增地表材质、通行属性和 LOD 生成器。
- [ ] 新增边界摘要、边界约束和邻接连续性校验。
- [ ] 新增关键实体跨分块索引。
- [ ] 新增完整世界烘焙命令。
- [ ] 新增单分块调试生成命令，但它不能成为运行时生成路径。
- [ ] 新增 Patch 应用、反向 Patch 和版本重建命令。
- [ ] 新增 `.gemap v3` 与 sidecar 打包/解包命令。
- [ ] 新增完整性、哈希和可复现性验证命令。
- [ ] CLI 至少提供 `generate`、`patch`、`validate`、`pack`、`unpack`、`inspect`。
- [ ] CLI 输出 `generation-report.json`。

## HTML 预览

- [ ] 保留现有 React/HTML 编辑器和 ASCII 地图能力。
- [ ] 战略地图继续使用 Konva/Canvas。
- [ ] 战略地图只加载 LOD 2 和场景/分块元数据。
- [ ] 新增 Three.js 2.5D 近景预览。
- [ ] 近景预览只加载当前视口附近分块，默认 3 x 3 或 5 x 5。
- [ ] 近景预览读取高度场、地表材质、实体索引和地标轮廓。
- [ ] 近景预览只实现 RTS 斜俯视，不实现自由 3D 模式。
- [ ] HTML 支持战略图与 2.5D 近景图切换。
- [ ] HTML 支持查看 scene_id、chunk_x、chunk_z 和 world_x/world_z/world_y。
- [ ] HTML 支持按坐标定位和显示地标信息。
- [ ] HTML 第一版不直接编辑大世界二进制数据。
- [ ] HTML 的修改请求通过 Agent 生成 Patch，再由 Rust CLI 重烘焙。
- [ ] CLI 提供 `glyphweave preview <world-dir>` 本地 HTTP 预览服务。
- [ ] 预览服务只读取静态结果，不触发地图生成。
- [ ] 生成结果可以部署到普通静态 Web 服务器。

## Godot 4.7 Adapter

- [ ] Godot 目标版本锁定为 4.7。
- [ ] Runtime Adapter 使用 GDScript。
- [ ] Godot 不承载世界生成、LOD 生成或 Patch 计算核心逻辑。
- [ ] Godot 直接读取 sidecar，不依赖每个分块预导出 `.tscn`。
- [ ] `.tscn` 只保存项目入口、相机、Runtime 配置和必要预制件。
- [ ] Runtime 运行时创建地形 Mesh、碰撞体和实体节点。
- [ ] Runtime 只保留相机附近分块节点，并自动加载/卸载。
- [ ] Runtime 支持 2.5D 环境浏览器模板。
- [ ] Runtime 支持可选 2D 平面化输出。
- [ ] Runtime 开发版显示坐标 HUD、场景、分块和 LOD 信息。
- [ ] Runtime 开发版支持按完整坐标搜索和作弊传送。
- [ ] 发布版默认隐藏调试面板和自由传送。
- [ ] 发布版仍保留 Manifest 声明的剧情传送点。
- [ ] Godot 启动时检查 Manifest、sidecar、版本和哈希。
- [ ] 缺失分块属于发布错误，不在游戏线程自动生成。

## Agent 工作流

- [ ] Agent 负责理解自然语言并生成 Manifest 草案。
- [ ] Agent 负责发现关键字段缺失并进行逐项追问。
- [ ] Agent 负责解释用户提供的风格和实体描述。
- [ ] Agent 负责读取生成报告并向用户解释错误。
- [ ] Agent 负责把地图修改转换为结构化 Patch。
- [ ] Agent 不直接生成数百万格高度、材质或二进制分块。
- [ ] Agent 不直接修改 Manifest、sidecar 或 gemap 二进制文件。
- [ ] Agent 不得静默改变用户指定的地标尺寸、位置、用途或剧情设定。
- [ ] 每次 Agent 修改前读取当前 Manifest、Patch 链、实体索引和边界摘要。
- [ ] 每次 Agent 修改后由 Rust CLI 校验并完整重烘焙。

## 自动验收

- [ ] Manifest schema 校验通过。
- [ ] 尺寸、场景数量、分块数量和 void 边界校验通过。
- [ ] Seed 重复生成结果一致。
- [ ] 所有相邻分块边界连续性校验通过。
- [ ] 所有关键地标坐标、尺寸和跨分块索引校验通过。
- [ ] Patch 链可以从原始 Manifest 重建当前版本。
- [ ] 反向 Patch 可以恢复上一个版本。
- [ ] sidecar 与 `.gemap v3` 内容一致。
- [ ] 所有 LOD 文件和哈希齐全。
- [ ] HTML 战略图可以启动并浏览完整场景索引。
- [ ] HTML 近景预览可以按视口加载分片。
- [ ] `glyphweave preview` 可以启动本地 HTTP 服务。
- [ ] Godot 4.7 项目无脚本错误启动。
- [ ] Godot 可以加载临近分块并卸载远端分块。
- [ ] Godot 坐标 HUD、分块定位和开发者传送可用。
- [ ] 输出 `generation-report.json`，记录警告、统计、版本和哈希。

## 实施顺序

- [ ] 阶段 1：整理 schema、Manifest、坐标适配器和 Rust 单元测试。
- [ ] 阶段 2：实现默认 1km x 1km 的完整 Heightfield 烘焙。
- [ ] 阶段 3：实现 512m 分块、边缘 void、LOD 和 sidecar 输出。
- [ ] 阶段 4：实现地标、资源槽位、跨分块实体索引和 Patch。
- [ ] 阶段 5：接入 HTML 战略图和 Three.js 近景预览。
- [ ] 阶段 6：实现 `glyphweave preview` 本地服务器。
- [ ] 阶段 7：实现 Godot 4.7 GDScript Runtime Adapter。
- [ ] 阶段 8：完成端到端示例、自动验收和生成报告。
- [ ] 阶段 9：根据 MVP 结果优化 Skill 触发词、追问流程和模板。
