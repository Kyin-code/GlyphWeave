# 西湖 1km 样板比例审计

## 结论

当前样板应称为“西湖北山-孤山-白堤 1km 窗口”，不能称为完整西湖。
公开资料中的西湖尺度约为南北 3.2km、东西 2.8km，水面约 5.66km²，
湖岸周长约 15km。一个 1km x 1km 场景最多只能表达其中一个局部窗口。

这次问题的根因同时存在于数据、规则和流程：

1. 数据层没有真实地点的 crop、坐标基准和来源事实。
2. 规则层没有材质/实体的允许地表、禁区、footprint、尺寸和标高契约。
3. 流程层没有在烘焙前做比例 dry-run，也没有把视觉检查作为交付闸门。
4. 旧生成器还曾用字符串中是否出现“西湖”触发水体逻辑，无法泛化到其他湖泊。

## 公开参考

- 杭州市文化广电旅游局《西湖风景区》：西湖面积约 6.03km²，水面约
  5.66km²，湖岸周长约 15km，平均水深约 1.5m，最深约 2.8m；白堤、苏堤
  将湖面分成五个部分，湖中有孤山等岛屿。
  <https://wgly.hangzhou.gov.cn/art/2024/1/16/art_1229733900_58952647.html>
- 《杭州西湖》公开资料：湖体最大长度约 3.2km，最大宽度约 2.8km，
  湖面海拔约 10m；孤山面积约 0.22km²、海拔约 35m；白堤长约 1km。
  <https://zh.wikipedia.org/wiki/杭州西湖>
- 杭州网《西湖三堤之苏堤》：苏堤长约 2797m、宽约 30-40m、高出湖面
  约 0.4m，并将西湖分为西小东大的两部分。
  <https://z.hangzhou.com.cn/2021/syjy/content/content_8115752.html>

不同来源的面积、深度和水面海拔存在统计口径差异，因此样板采用“本地湖面
基准 0m”，并把原始数值和来源保存在 Manifest 的 `style.referenceData`。

## 验收闸门

- `Source Gate`：来源、单位、crop、坐标基准和冲突说明齐全。
- `Semantic Gate`：每种材质/实体都有允许地表和禁用空间。
- `Scale Gate`：实体尺寸、建筑 footprint、道路宽度和水陆比例可追溯。
- `Continuity Gate`：相邻 1m 高度和材质不产生非设计突变。
- `Water Gate`：湖泊水面水平，岸线连续，波纹参数与场景类型匹配。
- `Visual Gate`：战略图、近景和 10m 视距截图可识别实际实体。
- `Feedback Gate`：视觉结果写入 `visual-feedback.json`，失败必须 Patch 后重烘焙。

## 工具缺口

当前 Core 已具备确定性生成、尺寸检查、部分水陆规则和连续性测试，但仍缺少
通用的 typed asset contract、GIS/GeoJSON 输入、通用水体 footprint 参数、
生成前 `scale-audit` 命令，以及对所有实体 footprint 的统一碰撞/贴地验证。
Skill 已规定这些闸门；在 Core 完成实现前，Agent 必须用独立审计补足，不能
把 `quality-report: pass` 解释为现实比例正确。
