## 1. 结论

**已运行并完成修复，可继续测试。**

本轮首次实际启动生成世界的 HTML 预览，而不是只检查静态文件是否存在。运行过程中发现生成产物的 `preview/index.html` 和 `preview/app.js` 被导出，但其 ES module 依赖没有一并导出，浏览器页面只能显示顶栏，画布保持空白。

## 2. 实测问题

初始预览目录只有：

```text
preview/index.html
preview/app.js
```

但 `app.js` 依赖：

```text
./core/shared.js
./core/camera.js
./core/state.js
./core/three.js
./core/world.js
./render/*.js
./render/presets/materials.js
./vendor/three/...
```

浏览器初始状态表现为：

- 页面标题和按钮可以显示；
- `scene` 下拉框没有任何场景；
- canvas 保持空白；
- 生成数据本身存在，HTTP 服务可以读取 `world.json`。

根因是静态预览模块依赖缺失，而不是 world JSON 或 baked scene 数据缺失。

## 3. 修复内容

文件：

```text
G:\difyllmwiki\GlyphWeave\bevy\crates\core\src\worldgen.rs
```

新增 `write_html_preview_modules()`，在每次 `generate-world` / bake 输出时复制完整 HTML 依赖树：

- `preview/core/*.js`；
- `preview/render/*.js`；
- `preview/render/presets/materials.js`；
- `preview/vendor/three/build/*`；
- Three.js loaders、controls、postprocessing、shaders 和 utils。

导出后的预览目录现在包含 **34 个静态文件**，可离线作为静态站点运行。

同时新增回归测试：

```text

```

该测试会实际导出模板并检查关键模块文件存在。
