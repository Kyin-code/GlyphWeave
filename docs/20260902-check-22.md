## 2. 本轮发现并修复的问题

### 2.1 无地标湖泊的默认几何越界

问题：当 Lake 没有 authored landmark 时，`water_geometry()` 复用了河流的整场景纵向半径，导致湖泊北岸道路中心落在场景外（例如 `z=-30`），尺度审计报告：

```text
generated.north-shore-road road center is outside baked heightfield
```

修改：

- 河流默认几何继续使用窄河宽度和全场景纵向跨度；
- 湖泊默认几何改用与既有 legacy lake 语义一致的 `0.38 * width`、`0.26 * depth`；
- 湖岸道路高度最低值统一约束为 `world_y >= 1`，避免道路落到 baked ground 以下。

### 2.2 pastoral 规划器住宅契约不一致

问题：Intent pastoral 生成的住宅深度为 `20m`，但默认 `residential_home` 资产契约要求深度不小于 `24m`，导致尺度审计对所有农牧住宅报错。

修改：

- pastoral 规划器的住宅 footprint 统一为 `24m x 24m`；
- 保持其边界检查和建筑占用检查不变。

### 2.3 quality-report 对 Intent 场景语义判断过严

问题：

- pastoral 规划器不是完整的 urban/rural/nature 比例拟合器，却被要求与默认 profile 比例比较；
- wilderness 明确跳过 land-use profile，却被错误产生 warning。

修改：

- 结构化水体显式定居规划器不进行普通陆地比例拟合；
- pastoral 只报告生成结果，不伪造比例达标结论；
- `naturalOnly` 是显式语义，不再产生 profile 未应用 warning；
- 没有显式 planner 的结构化水体 Manifest 仍会保留提示，避免掩盖真正的适用性缺口。
