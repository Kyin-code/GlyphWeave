# 外部高级审查意见：ABC 主线与后续能力分期记录

日期：2026-09-29。性质：**外部审查意见登记与内部分期回应**。

本文件记录一位外部高级 Agent 在阅读项目当前资料后提出的审查意见。意见已完整归档，但**不等于新增需求全部批准、不等于当前实现已具备相关能力，也不改变 A/B/C 当前状态**。

当前产品裁定仍为：

- A：稳定底座历史签收保留；内容例外仍需按实际证据处理，不重新开启 A-FINAL；
- B：整体 `partial`，当前主线仍是道路—地块—建筑—入口—设施—用途的真实生产闭环；
- C：未整体完成，须在 B 接口稳定后分阶段推进；
- 当前 B01-R1：T0/T1 已完成，T2 按 OPT-B 实现基础道路 profile 消费链，T3/T4 仍按既有任务书执行；
- G27-G35 局部预览/消费者工作不能替代 ABC 生成能力；
- 本文件不授权立即实现全部下列项目。

## 1. 外部意见的核心判断

外部审查认为，当前资料除了具体生成缺口，还应关注以下长期架构问题：

1. Patch/revision 若带有年代与演化语义，可以成为历史分层的基础，但 Patch 本身不自动等于历史模拟；
2. 没有统计级人口与需求分母，公共设施的合理性难以验收；
3. 现代世界基线缺少市政基础设施骨架；
4. 区域规则应从散落启发式收敛为版本化参数包，包括左行/右行、退界、日照、密度等；
5. 真实城市允许空地、混合用途、临时用途和未完成状态，质量模型不能只表达“全闭合”；
6. 地名、街道名、片区名具有较高的真实感收益；
7. urban/rural/nature 之间需要显式过渡带；
8. 访问图未来需要区分私有、门禁、服务时段和应急访问；
9. 仅有硬约束还不足以证明形态合理，需要统计分布诊断；
10. 荒谬探测应形成可持续扩展的规则库；
11. 约束冲突需要失败、修复、妥协和未解决的分级策略；
12. 即使材质延后，生成器与消费者之间的几何/性能合同不能延后；
13. 来源层可视化比材质精修更能帮助用户理解可信度；
14. 最大图连续消费隐含 LOD、流式加载和数据组织要求；
15. 导出与互操作不应完全缺席；
16. 并行生成可能破坏 seed 复现，需要确定性政策；
17. 6×10km 的存储、加载和内存预算需要数字化实测；
18. 普通地形、道路、河流等跨 chunk 接缝需要系统测试；
19. 需要固定黄金场景做持续回归；
20. 线性 revision 未来可能需要 what-if 分支和方案比较；
21. GIS 导入必须在输入合同中处理 ODbL 等许可义务；
22. 过程文书不能替代能力产出，每项交付必须有机器可核验产物。

## 3. 应立即进入 ABC 共同底座的事项

这些事项不意味着重开 A-FINAL，而是作为后续 B/C 修改必须遵守的护栏。

### 3.1 确定性合同

至少要固定：

- chunk 子 seed 派生；
- 实体和候选的稳定排序；
- map/set 的遍历与归约顺序；
- 毫米/整数与浮点计算的边界；
- 跨平台允许的数值误差；
- 生成器、规则包、输入数据和算法版本；
- 哪些字段要求逐字节一致，哪些字段使用数值容差。

### 3.2 分块、存储和消费者合同

至少要有实际数字：

- 单 chunk 与整图存储大小；
- 生成、首次加载、重新打开时间；
- 峰值内存；
- chunk 流式加载顺序；
- 跨 chunk 实体归属；
- 空间索引粒度；
- 每 chunk 实体/几何预算；
- 生成真源与消费者派生数据的边界。

这不是材质任务，也不是要求现在完成最终视觉渲染。

### 3.3 接缝与黄金回归

固定场景至少覆盖：平坦城市、缓坡城市、山地边缘、农村、荒野、水体边缘、多 chunk 世界和包含明确 unresolved 的世界。每次生成器改动都比较：

- 计划与实际数量；
- 道路/地块/建筑/设施摘要；
- ledger；
- 失败和拒绝分类；
- chunk 接缝；
- 生成与加载性能；
- 关键 hash。

### 3.4 交付证据纪律

后续任务必须区分：

- 需求已登记；
- schema 能表达；
- 生产代码已接入；
- fixture 已通过；
- 真实世界已观察；
- 跨场景/最大图已通过。

不能以测试数量、文件数量、截图数量或纯文档数量代替业务能力。

## 4. 应进入 B 主线的内容

### 4.1 轻量人口/需求模型

B 不需要完整经济系统，但需要最小需求分母：

```text
parcel → dwelling capacity → population estimate → service demand → catchment
```

第一版可以只支持户数、人口区间、基础商业需求、学校/医疗/消防容量和步行/道路覆盖。设施缺口必须进入质量报告，不得因为“设施已存在”就判合理。

### 4.2 RegionRulePack

第一版应至少能表达：

- 左行/右行；
- 道路宽度和交叉口；
- 退界与日照/间距近似；
- 地块最小尺寸；
- 高度、层数和覆盖率；
- 消防通达；
- 停车/公共交通偏好；
- 来源、版本和适用范围。

它应是数据化、可版本化的规则包，不把某一地区的隐含假设硬编码进生产函数。

### 4.3 过渡带、荒谬规则和冲突策略

B 需要把 urban/rural/nature 之间的硬切换改成可解释的过渡语义，并将常见荒谬情况沉淀为规则包。每条规则需要严重级别、证据位置、修复建议和版本。

冲突处理要区分：

- 必须失败；
- 可有限修复；
- 可生成但标记为 compromised；
- 未解决但保留缺口。

“缺陷预算”只用于预先声明的真实不完美，例如空地、混合用途、临时状态，不得吸收真实硬失败。

### 4.4 基础市政骨架与命名

B 后续可以先加入市政走廊、基础点状设施和容量字段，而不是立即实现完整管网。道路、地块、街区、河流、地标可以增加稳定名称，但名称不得影响规划结果。

### C 阶段

- 自然—工程—人文反馈；
- 工程地形、水文、排水和洪水影响；
- 完整市政网络；

- 统计分布质量门槛；

### C 后或 FUT

- 完整历史城市演化；
- Patch 分支、what-if、diff、merge；
- LLM 非内置建筑/地貌规则 Recipe；
- 公里级复合设施拆分与组装；
- 现实地名/GIS 分层重建；
- 复杂人口、经济和交通时间模拟；
- 完整多格式互操作插件。

这些项目与既有 FUT-01～FUT-06 的对应关系，仍以 `c-post-c-six-capabilities-plan-20260929.zh-CN.md` 为准。

## 6. 与当前 B01 任务的关系

本外部意见不改变当前任务优先级。当前最小主线仍是：

```text
base RoadEdge
→ authoritative RoadProfile
→ RoadNetworkPlan::entities()
→ frontage::stations()
→ candidate site
```

在 B01-R1 T2/T3 尚未闭合前，不启动人口模型、GIS、历史模拟、完整市政网络、动态访问或开放式 LLM 规则实现。否则会把当前真实业务缺口分散到多个未闭合系统。

T2/T3 完成后，下一份任务书可从本文件的 B 项中选择一个窄包，优先顺序建议为：

1. 轻量需求分母与服务覆盖；
2. RegionRulePack 第一版；
3. 过渡带与 AbsurdityRulePack；
4. 基础市政骨架；
5. 黄金语料与统计诊断整合；
6. 命名系统作为低成本体验增强。
