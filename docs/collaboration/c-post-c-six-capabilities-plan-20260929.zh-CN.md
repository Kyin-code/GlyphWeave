# C及后续扩展：局部自然语言编辑、开放规则、复合设施、环境推断、GIS与重现模式

日期：2026-09-29。来源：用户在B主线夜间任务已交出后补充的需求。本文件是未来需求登记与建议分期，不是这些能力已实现的声明；不改变DSH当前B任务，不要求停下B去重构或实现全部扩展。
用户列了5个编号，称“6点”；这里把第2项拆成“开放世界规则与新生成器”及“公里级复合设施拆分组装”两个工作包，形成6包。若用户另有第6项，本清单可追加，不杜撰遗漏项。

## 0. 周期与范围原则

- B：继续真实现代世界生成；只避免锁死稳定ID、依赖、来源、规则作用域、复合结构等接口，不给正在运行的任务追加实现闸门。
- C-core：完成原C自然—工程—人文闭环；纳入本来就有的Patch需求之最小可用局部编辑、环境背景/假设机制、版本化重放合同。
- C-extension / 暂称D：开放式新类型生成、幻想/科幻规则包、跨公里复合设施、GIS产品化导入。本名称仅为排期标签，不冒充已存在的正式里程碑。
- GIS若用户未来提供数据并优先要求，可作为独立支线前移；不得在B尚未闭合时默认开展城市GIS复刻。
- 渲染、材质精修仍非本轮重点。需要浮空/多层体量时，必须扩展权威几何/连接/审核能力，不能只在viewer画出来。
- 新扩展不全部挤进原C完成条件或此前的周级冲刺目标；实际选入的最小功能与后续完整扩展分别验收，不能静默延长原C后说原计划未变。

## 1. 总体架构建议

用户描述/选区 + 已保存世界 + world rules + 用户/GIS证据
→ LLM提议（允许启发式，非权威事实）
→ 意图/规则/影响范围审查与必要确认
→ 版本化WorldPlan、Recipe或Patch（机器可验证）
→ Rust执行生成/重建/冲突检测与独立审核
→ 新WorldRevision + 来源/假设/受影响范围 + 可回退产物。

把“LLM理解与设计的开放性”和“运行程序的确定、有限、可检查执行”分开。LLM不直接改几百万格二进制，也不因它说合法就跳过碰撞/保留对象/规则一致性审核。

## 2. 扩展要求与分期

### FUT-01：生成后的自然语言局部修改

用户原意：构建之后能让LLM只改局部，而非重做整个世界。这也是早期glyphweave-world-todo中Agent→Patch→按影响范围重建的延伸，不应被遗忘成纯新增需求。

放置：C-core先做受限可用版本；大范围多目标、复杂自然因果编辑在C后扩展。

最小流程：
1. 绑定基础worldRevision、选区/实体ID和用户意图，例如“只把这片仓储地改为住宅，保留主路和河岸”。
2. LLM产出typed Patch：操作对象、增删改、前置条件、保留清单、预估受影响依赖、假设与理由。
3. 给用户简短预览：改变什么、不变什么、影响哪些街区/通路/地表；需动到用户保留对象或扩大范围时确认。
4. Rust计算依赖闭包：实体/parcel/道路/访问图/工程地面/水文/LOD索引；只重建必要部分，原world不覆盖。
5. 原子提交或完整回滚；旧revision冲突必须拒绝/重定位，不用新旧混合状态发布。

“局部”不是只画一个框：移河、截断主干道、改大坝可能影响框外。要分直接编辑区与传播影响区；无法在批准范围保证一致时说明影响并请求扩大，不能口称局部而暗中重生成全世界。

验收：局部建筑替换/增删与一例受控局部地形编辑；未受影响实体ID、几何及权威数据哈希保持（全局索引/revision元数据允许显式必要更新）；依赖内地表/路网/LOD同步；过期Patch、越权改保留物、边界缝隙、失败回滚、重复提交均有反例。增量结果与基于同一已批准计划的参考结果核对，而非要求重新询问LLM得到一样的话。

### FUT-02：LLM能提出并生成内置类型之外的建筑/地貌规则

用户原意：不局限于预设现代kind；天空教堂、浮空城、未来朋克世界等应能按其设定进入项目，并有世界内的合理性。

放置：C中预留规则作用域和外部生成包接口；完整可用能力放C后。其目标不是“再手写几个新kind后宣称开放”。

三层实现建议：
A. 组合已有语义原语：体量、平台、洞口、路径、桥接、地形操作、空间保留区、支撑/入口/交通端口，LLM产出新的参数化Recipe。
B. 声明式扩展：用受约束DSL定义可检查的空间/拓扑/生成规则，记录单位、输入输出、终止/资源边界、冲突优先级和版本。新Recipe可以不在原内置建筑枚举中。
C. 真正缺少原语时：LLM提交新生成器插件及测试，进入隔离编译/验证/审批，再注册能力；不得自动把任意生成代码拿到宿主权限执行，不能让插件自签自己的安全约束。CPU/内存/IO/网络/版本/许可边界明确。

合理性由有作用域的world rules决定，而非一套“全部必须贴地”的现代默认规则：
- 现实现代基线保留，区域/设施可以显式引用magic/fictional-technology规则包，作用范围与过渡边界明确。
- 浮空城可以声明悬浮支撑假设；保留碰撞/占用/身份/通路/保存一致性约束，而非全局关闭接地/碰撞。
- 天空教堂“天空顶上不被覆盖”不能擅自解读为删除教堂屋顶：需区分露天内部、屋顶上空禁占空间、特定方向开阔视域。把确认后的条件写成clearance volume/sky exposure等可测合同；遮挡物类别、距离/高度范围明确。
- 未来朋克不是默认换霓虹材质：先提用途、交通、垂直层级、能源/设施和街道组织的规则草案，仍由用户确认风格/关键世界设定。
- 现代环境被幻想设施替代的范围、访问方式（步行/升降/飞行等）、周边接驳和对原设施影响有明确逻辑。

验收：一个未出现在内置kind名单的新Recipe真实生成并保存；一例浮空/多层对象不把非法悬空普通建筑误放行；sky约束阻止后续对象侵入；世界规则冲突给解释；未知生成器不伪装可用。存在渲染模型不等于新规则进入生成和审核。

### FUT-03：公里级复合设施拆分、组装与跨块一致性

用户原意：质量投射器、天钩或长电磁加速轨道等设定可能跨数公里，需要拆开生成再组装。原文涉及不同设施设想，本文件不将这些名称当成同一种工程设计，也不替用户作现实可行性结论。

放置：B/C现有跨块ID/道路/结构接口可复用；C验证基础装配接口；完整复杂科幻设施放C后。先做静态几何和连接一致性，不默认增加发射动力学、轨道力学或真实工程安全认证。

数据层：site/assembly→subassembly→components。每个整体有global ID、整体路径/包络、基准坐标；部件有局部变换、模块类型、接口端口、容差、支撑与通行、服务连接、来源版本。

先整体规划走廊/占地/净空/地形影响和约束，再分段生成；不能独立生成一堆零件最后发现接不起来。跨chunk是一套整体身份和接口，不按chunk复制整栋/整设施。区分“适配器不够细”与“实际断接”。只改某段时按依赖更新，不无谓重生成全轨道。

验收：多公里、跨多个512m streaming chunks的非空连续设施；接缝位置/朝向/标高和连接拓扑一致；重访/卸载无重复缺件；局部替换与全体ID稳定；跨当前最大场景范围的设施需明示scene graph/外部端口或另行尺度扩展，不能静默截短。接口容差按模型合同设定，不伪称现实建造标准。

### FUT-04：世界背景、地理气候推断与显式假设

用户原意：用户不把洋流、季风、气候、造山背景逐一说全时，LLM仍应合理处理或给出假设，避免每个专业参数都让用户填。

放置：C-N自然主线。最小目标是有因果约束的环境背景，而不是在C首版实现完整全球气候/板块模拟。

建议分两层：
- 区域背景：位置/纬度或虚构区域、年代、地形骨架、海陆关系、主导风/季节、温湿条件、水系边界、地质/造山设定。
- 本地生成：把这些背景转为terrain/hydrology/biome/农业/聚落适宜性约束。几公里窗口不能被要求仅凭本地格网“推算整个海洋”，区域场是输入，不伪装为本地仿真输出。

事实/推断/假设分开：userProvided、importedObserved、derived、assumed、unknown，每项来源、依据、适用尺度、置信/证据等级和对生成的影响。置信等级不是无依据概率。

缺省交互：
1. 普通低影响参数可按用户允许的“合理补全”政策生成，并在简明假设表披露。
2. 改变主要地貌/地标/世界物理规律、重大用地与硬需求的高影响缺项，合并成少量关键问题/候选方案确认。
3. 现实地名且有可靠数据，优先事实；不能用LLM猜测覆盖观测。
4. 虚构世界允许按其规则生成，但内部因果要一致；与用户明确描述矛盾时指出矛盾，不静默替换。

验收：相同地形、不同主导风/湿度/季节背景产生有解释的生态/水文差异；假设替换后只更新依赖结果；现实事实与虚构假设在报告中可分；一例数据不足、一例明确规则冲突。只声明采用简化参数化，不能称为真实全球预报/板块历史重建。

### FUT-05：现实地名与GIS近似重建

用户原意：给现实地名、尤其给GIS后，能够大致还原地形地貌及现代人文布局。

放置：C保留坐标/来源与导入接口；GIS近似重建作为C后独立产品工作包，可按用户数据需求前移。

三种模式分别验收：
1. 只有地名：消歧地点/范围/时间；经允许获取可用数据。若只有知识描述，就输出“地方特征启发的合成场景”，不能冒称实际街道/建筑还原。
2. 部分GIS：高程、水域、道路/建筑轮廓/土地利用等可用层作为锚点，缺失高度、用途或设施用规则补全并逐层标为推断；不由DEM凭空声称已恢复真实建筑。
3. 足够GIS：保留实际道路/岸线/建筑轮廓及语义，在数据分辨率/时间范围内重建；细节缺失照实标记，不承诺精确照片级现实。

导入前固定：数据许可与出处、获取时间/观测年份、水平CRS/轴顺序、水平/垂直单位与高程基准、空间精度、NoData/缺层、local origin转换和边界裁切。多源冲突不可静默覆盖；不可通行/桥梁/隧道层次不能仅凭2D线相交连通。

验收：一个经许可的有限区域；导入锚点位置/高程误差在预声明且不高于输入可信程度的容差内；道路/建筑语义与来源可回查，观测与补全分别量化；GIS更新局部Patch；删除一层数据不把合成猜测冒充还原精度。现有数据→内部标准世界模型→既有生成/审核/消费，不另建孤立演示器。

后续GIS技术预研可从GDAL坐标转换与OGC CityGML语义模型入手。本次仅登记候选方向，未核实具体版本/适配性，不引入依赖，不把实现整个外部标准作为第一包的前置要求。

### FUT-06：种子与LLM参与后的重放分离

用户明确希望：纯代码与预设生成才对用户承诺“种子复现”；LLM介入不要把相同seed每次必须得到相同推理结果变成拖延点。

采用以下对外模式设计：
|模式|用户入口|复现承诺|记录|
|---|---|---|---|
|procedural / preset|seed + 确定版本preset/config|固定输入和引擎版本下重现；跨平台精度范围另定|seed、preset/config、版本/算法、输入数据|
|assisted / LLM|自然语言 + 世界/用户约束|不承诺重问LLM得到同一结果，不以seed作为整世界身份|用户请求、已采用的结构化plan/recipe/规则包/假设、输入快照、版本、来源|
|edit / Patch|已保存revision + 已批准Patch|重放已接受操作得到可核对结果，不重新询问LLM|基础revision、Patch、作用范围、依赖、before/after、生成器版本|

LLM模式的Rust执行层内部可以冻结随机流或子seed作为运行数据，但不向用户宣称“只凭seed就重现整个LLM世界”。优先保存已产出的有效计划、程序化配方和实际世界产物；LLM换供应商/模型或再次采样属于新提案。

ReplayBundle建议至少包含：world/plan revision、已批准plan、recipe/plugin版本与hash、resolved随机参数（若有）、用户规则和假设、GIS/source快照hash、Patch链、引擎版本、结果校验。摘要/模型名不是完整重放证据；模型日志只是来源辅助，不要求保留模型私有思维过程。

不要求模型任意跨版本输出位级一致；Rust端同一已编译计划的可重复性与几何一致性仍保留。昂贵或难于跨环境严格重建的导入/生成结果可冻结产物，明确重放等级，不伪称所有环境位级确定。

验收：同一冻结plan离线重放不调用LLM；不同LLM输出不因相同seed被错误当同一世界；缺recipe/plugin或GIS输入拒绝“完整重放”；局部Patch重放/回滚不重新生成整世界。

## 3. 六个包的依赖与建议开发顺序

1. 当前B继续；此文件不追加今夜实现任务。DSH只需知悉不要写死“所有对象贴地、所有设施是单盒子、整个世界只由seed身份决定”等假设，遇必需接口冲突报告。
2. C开工时先落FUT-06版本/来源约定、FUT-04环境背景合同；FUT-01用已有Patch机制做受限局部修改闭环。这三项按原需求继承与用户新授权形成单独小任务，而不是一口气改全部核心。
3. C主体仍按原自然—工程—人文任务完成。
4. C后先FUT-02受限Recipe/规则作用域与FUT-03装配；再按需要上受审插件，不能用永远只支持内置枚举的“开放”接口敷衍。
5. FUT-05单独排可用GIS小区域工作包；用户已有数据时可优先于幻想插件，不阻塞现代B/C主线。
6. 全球动态气候、真实板块长期演化、天钩/电磁发射的物理工程验证、任意代码即插即用均不默认授权；如用户需要另列专门研发目标。

## 4. 与旧合同的明确衔接（不能默默改要求）

- 旧“seed+manifest是唯一真源”今后仅适用于procedural明确模式；assisted的权威身份改为已批准Plan/Recipe/Patch/输入数据/版本的组合。旧世界仍按旧schema解释，不修改其seed/历史hash。
- 旧“关键字段缺失必须追问”保留到硬约束/高影响决策；在用户允许合理补全时，低影响参数可以显式假设并披露，不能将世界规则/位置/尺度任意当低影响。
- 旧“自然源不可改”是保留原自然输入与来源、不污染历史；用户批准的局部地貌操作产生新revision及影响记录，不是禁止编辑。
- 旧现代地面支撑规则不直接套在获批准的浮空规则区域；仍需一套可验证的支撑/通行/空间占用解释，不能删除所有安全检查。
- 多公里装配不能把当前6×10km最大场景默默扩大；跨场景先按已有scene graph，新的尺度另定运行合同。
- 新能力是否完成以实际执行、保存、审核、重放为准；文档登记、规则schema、LLM会描述设计、viewer能画出东西，均不等于能力交付。
