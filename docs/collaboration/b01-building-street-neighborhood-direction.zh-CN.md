# B01：建筑形态、街道界面与新老城区的设计方向

日期：2026-09-20。用户在G19执行期间提出：建筑应有双塔/大楼/联排/小区/园林/滨海景观/外卖小店/写字楼/夜市帐篷等形态，道路与建筑应有真实空间和小路关系，并考虑老城区与新城区。

本文件是源码现状核查与产品需求登记，不是新执行任务。不打断、不扩写正在进行的G19；不改源码/默认值/自然权限，不宣称下列新能力已经实现。

## 1. 已有基础与明确缺口

本次只读检查范围及依据（均位于G:/difyllmwiki/GlyphWeave/）：
- docs/modern-mainland-morphology.zh-CN.md 已有多国城市资料入口及归纳基线；案例名/门户链接不等于已逐项标定的真实测量数据。
- bevy/crates/core/src/settlement/morphology.rs 有6类profile：compact-mixed-block、perimeter-block、low-density-residential、clustered-residential、terrain-constrained-compact、village-field。包含地块尺寸、前侧后insets、高度、覆盖率、道路层级、公共空间比例等，内置证据级为heuristic。
- morphology_compile.rs 已将部分profile编入实际消费者参数，区分original-input/profile-default/derived/unsupported；范围默认取中间值，不能仅凭配置范围认定最终建筑形态已多样化。profile不是第二个完整布置算法。
- worldgen.rs 的EntityInstance提供尺寸、朝向、asset、grounding、anchors、bounds等；CityForm有DenseCore/RiverDelta/CoastalBay/MountainValley/TemperatePlain/LowDensitySuburban；已有滨水布置函数和店面/树/步道等布置逻辑。因此“所有建筑只有一个固定方盒”或“滨海完全未考虑”均不准确。
- worldgen/frontage.rs 当前显式program只接residential_home/residential_block/storefront三种；宽深为受限偶数尺寸，setbackM为8..32偶数米。candidate_site在轴向道路上按road.depth/2+setback+building.depth/2偏置。这是该消费者的工程约束，不是现实城市普遍退距。
- worldgen/parcel_geometry.rs 当前是整数矩形地块及0/90/180/270方位，insets前/侧/后可不同；legacy为2/2/2。不能将此地块余量和道路边缘退距混为一谈。
- settlement/development.rs 有建筑、地块、yard等真实计划与审核；settlement.rs有district/parcel/public_space/building_relations。其一种派生图按用途分组并依据实体形成地块关系，不是历史城市增长模型。

本次已查模块未发现明确的建设时期、旧路保留/地块拆合/城市更新时序模型。不能断言全仓完全不存在任何相关资源，也不把district节点当成已实现新老城形态生成。

## 2. 建筑需求不能全部压成kind标签

建议表达层次：district→block→parcel/site→building ensemble→building parts→storeys/use units→entrance/connection ports→landscape/temporary operations。

|用户需求|需要的生成对象与关系（待开发）|
|---|---|
|双塔/多塔综合体|共享地块、裙房、独立塔体、不同标高体块、可能的连廊、多个入口；不能只随机放两个大楼|
|大楼/写字楼|塔楼或板楼体量、裙房/大堂、办公与底商使用单元、后勤和车库入口；用途与形态分开|
|联排别墅|重复单元、允许共享墙、每户入口/院落、端头与转角单元；碰撞规则区分有意贴合和非法重叠|
|小区|多栋建筑、组团、开放/受控边界、门、内部车行/步行网络、社区设施与景观；不是一个大盒子实体|
|园林/小区景观|路径、场地、植物群落、水体、活动空间、景亭和视线组织；景观要有可达入口，不只是空余地撒树|
|滨海景观|滨水公共通行、面水界面、到水边的公共接点与地形/水域约束；不能所有沿水地块被私有建筑截断|
|外卖小店|经营单元/功能，不必新建独立建筑；店面/后场厨房、取餐入口、骑手停留与配送接驳，不占满连续人行空间|
|夜市帐篷|临时设施组、摊位朝向、摊间通道、占用时段、装卸/服务；不等同永久住宅障碍体|

形态至少考虑矩形、L/U型、围合庭院、有洞多边形、板楼/塔楼、裙房上塔、阶梯退台、沿坡错层。外包围盒只用于粗筛，不可把中庭/穿楼公共通道填成不可穿的实心体；细几何、碰撞、通行与占地统计须一致。

数据中区分geometry、use、ownership/access、construction cohort、condition/renewal、operation schedule，不以“旧/新/豪华”一个标签同时决定所有属性。

## 3. 道路与建筑：不是一个间距数字

必须明示五类量：道路中心线到道路边；道路空间/用地边界；边界到建筑立面退界；地块边界到建筑inset；门到可达网络的实际路径长度。不能混用，也不能从最近道路距离推出入口可达。

街道断面应组合表达：车行部分/路缘设施与绿化/自行车或步行空间/临街活动区/地块前场/建筑界面。顺序、共享或独立设置取决于场景，不把此列表写死为所有道路的固定断面。

间距没有项目通用真实常数。已有8..32m限制不适合直接推广到全部紧凑商业街、骑楼/沿街店铺或大型园区。规划应先决定界面类型与各空间宽度，再计算立面位置，数值来源分为案例测量、项目启发式、用户指定及明确地区规则。切勿给某地区标准套全国。

建议界面模式：连续贴街、浅前场/台阶、前院住宅、塔楼前广场、沿街裙房+后退塔楼、临水步道界面、沿坡多标高入口。地面0退界不代表建筑门直接开进车道，也不取消公共人行空间。

小路必须是网络：街巷、支路/辅路、小区内部车行、宅间步道、后巷服务、园路、骑楼/穿楼通道、楼梯/坡道/电梯连接。每条有宽度、表面、方向、通行者、开放性/门禁、端点身份；绿化缝隙或地块空白不能自动算路。配送、住户、公众步行、车辆和应急服务不能一条路径全包。

多栋小区应允许“楼门→宅间路→小区门→公共人行道→路口/站点”的层次化连接，而非每栋强迫直连最近主干路。当前固定ST18的指定BC验收不暗改；未来新合同要区分街区网络目标与某一楼栋的直接接点。

## 4. 新老城区：空间形成过程，不是贴图新旧

建议使用两个独立维度：形态/发展模式 + 建成年代/后续更新。老城不必杂乱低矮，新城也不必大路巨块；不以单一刻板模板覆盖所有城市。

首批可讨论原型（均为设计提议，不是当前实现）：
- 历史混合街区：保留骨干街巷和细地块，多年代建筑、底商/住宅混合、局部修缮与填充。
- 既有计划住宅片区：成组住宅、院落、增设服务/停车/电梯等更新，但保留既有空间身份。
- 新建综合片区：一次性道路/地块规划、公共设施和开放空间预留，可为小街区或大组团，不强制巨块。
- 旧工业/港区转型：保留部分厂房、轨道或岸线结构，插入新用途和新的公共网络。
- 山地/滨水复合片区：历史台地、岸线或沿坡路与新工程并存，多标高入口，视地形选择楼梯/平台/桥/挡土/挖填。

建议生成流程：冻结地形/水系与需保留对象→骨干网络和发展阶段→片区形态/街坊/地块→建筑组团与界面→内部交通和公共空间→小尺度设施/经营活动→联合检查。道路和建筑需求要有有限反馈调整，不能完全先摆建筑再最后勉强拉线。

保留/改造/拆除/新建用显式操作与来源记录；历史保护对象、普通旧建筑和新建结构的可变性分开。城市更新不是全部拆平，也不是全部禁止改变。生产初期可以直接生成“经过若干发展阶段后的静态结果”，不要求先开发完整经济/人口历史模拟。

## 5. 如何接入后续任务，不打断G19

G19优先完成其已批准楼梯/平台/受控整地生产链。后续城市空间任务应复用该链，而不是另建一套只画楼梯的建筑特效。

下一阶段选一个有对照的街坊级完整样例，检验：不同体量组合/多入口、街道断面、共享步行网络、公共/半公共/私有层次、跨标高连接和地块用途是否一致。然后把同一需求用于不同片区profile，不以改随机种子或颜色冒充新老城差异。

每种能力逐层登记：需求已纳入→模型可表达→可生成→可达/碰撞/空间审核→持久化与可见几何→真实输入验收。当前未验证的双塔、联排、小区内部网络、新老城过程不提前填“已支持”。本文件不新发并行实施任务、不增加自然额度。

## 7. 真实感优先级与跨尺度工程覆盖（2026-09-20，用户进一步要求）

### 7.1 现在的节奏决定

用户主要目标是真实感，不接受长期只有基本逻辑/测试报告；补充机场、高速、普通铁路/高铁/内部货运、体育场/大学/教堂/消防设施、人工林、索道、盘山路、人工湖、港口、跨江跨海及传统桥梁等。

基础逻辑先做并非错误，但不能承诺所有大系统最后补上都不返工。按“影响规划拓扑/占地/自然状态的内容现在预留，具体生成器和视觉细节分期实现”组织。不打断G19R1碰撞/假通行修复，不把新设施塞进其白名单；那是后续所有结构可信的前提。

本节合并路线而不新增实施任务。下一轮正式开发前用一次有界接口/规划审查确认，不再围绕每个名词开一包纯文档，也不以“列入需求”冒充已经支持。

### 7.2 必须现在考虑，而非以后贴模型

|类别|现在需要的规划/数据约束|可后续分期的实现|
|区域枢纽：机场/港口/铁路客货站/货场|大面积连续用地、与城市边界外网络的接点、模式/客货分离、服务/集疏运接入、相邻用途关系；机场或港口不强制每城配齐|航站楼/码头/站房模型，详细作业设施和运行模拟|
|高速/普铁/高铁/城市或厂区货运|网络身份/等级、方向、曲线和纵断面、交叉分层/有限接入、连接目的地、跨scene/chunk边界；不能把所有线都当local road|多类型线形优化器、匝道细节、列车/车流仿真|
|大学/体育场/宗教/消防等公共设施|校园/场馆作为多对象site而非单盒子，多个出入口、到达和服务需求、公共/受限区域、服务覆盖；选址与文化/规模相适应|立面/座席/室内/精细景观及人员活动|
|桥梁/索道/盘山路|两端真实连接、跨越/承载/层级和净空、对地形水域的影响范围、连续曲线/地形适应；不得依靠2D相交自动接通|传统/拱/梁/斜拉等具体桥型、索道站/塔、视觉风格|
|人工湖/水库/港池/岸线工程|自然水体与人工改造分别记录，显式工程后的岸线/水面/地表、进出水或设计水位边界、对路网/地块的连带影响；不能只刷蓝色覆盖碰撞|复杂水工过程、动态洪水/泥沙/港池仿真|
|人工林/防护林/农林景观|自然生态与人工经营用途分开，经营地块、通路/界线/种植形态、建设与保护来源|树种/树龄/冠层细节和经营时序|

这是本项目拟采用的需求拆分，不是现实工程规范或当前功能清单。机场/高铁/大学/教堂等不是按城市人口一个阈值机械必选；先由地理、区域角色、使用需求、文化和建设时期决定哪些存在、哪些在场景外通过网络连接。

### 7.3 六项必须避免锁死的基础假设

1. 所有可走表面都是单层地形——G19正开始解除，但需先完成实体碰撞和身份审核。
2. 所有设施都是一个矩形实体——保留包围盒粗筛，同时支持site/compound/子结构/多端口真实几何关系。
3. 所有交通都是一类road，靠近就能接——维护模式/方向/转向/等级和实际端口；客货与普通步行连接不同。
4. 自然永远不可改，或修改后完全覆盖自然来源——保留原natural、工程计划/变更量、最终工程状态，所有消费者一致读结果。
5. 地块先占满，机场/线路/水利最后找缝塞——总体阶段有用途/走廊/重大设施预留，未实现部分标reserved/unsupported，不伪造已建资产。
6. 人工fixture的64m网格/对象上限变成产品世界尺度——测试上限不等于真实规划上限。区域粗规划与局部细生成共享坐标/身份/连接；跨区基础设施不能被chunk切断，未细化也不冒称具有可审核几何。

G19独立sidecar不自动保证全世界一致：未来render/physics/access/audit及水体/土地使用都要消费同一工程版本，不能画了桥而寻路仍走下面、挖了湖而建筑审核仍读旧陆地。

### 7.4 交付节奏：可靠基础之后必须有可见、成体系样例

1. 先完成G19R1，停止穿墙/假通行，不再扩大其任务。
2. 下一阶段合并城市/区域规划接口检查与一个有限的可见综合样例：不是先写完整百科架构，而是明确总体预留、街坊/site、局部结构的输入输出，然后实现一个可运行纵向切片。
3. 综合样例建议选择有地形差异和滨水条件的片区：能看出道路层级、真实出入口、建筑组团、公共设施/公共空间与人工工程的因果关系。尚未实现的枢纽只画规划预留图并明确未建，不拿预留当最终城市场景通过。
4. 再按依赖分包扩展区域交通/枢纽、多形态建筑与公共设施、人工地貌与景观；每包有实际几何和整体视图，不只给字段/测试PASS。

不要求同时包含机场、港口、高铁、索道和所有桥型才算样例成功，也不让每个城市长成同一套设施拼盘。

### 7.5 真实感验收不等于截图好看

除技术回归，必须展示并检查：
- 位置/尺度/上下游关系是否说得通；道路、桥梁、站点是否有合理起止，设施是否有公共与服务接入。
- 同一输入在总览、街区和近景中是一套几何/身份，LOD不能改变可达事实；没有悬空、穿墙、断桥、断头接线和伪入口。
- 建筑形态有组织的差异：site/地块/道路界面关联，不靠随机缩放和随机颜色冒充丰富度。
- 人工林/人工湖/港池等在用途、地形、水域和运行约束中存在，不只是材质替换。
- 明确哪些是启发式设计、真实案例标定、人工fixture、已建几何、规划预留、未实现；不因类型覆盖表很长而宣称城市真实性已解决。
