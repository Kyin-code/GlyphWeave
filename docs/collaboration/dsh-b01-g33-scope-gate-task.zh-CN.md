# DSH B01-G33：范围与验收合同闸门

日期：2026-09-28。依据 `b01-g32-final-verdict.zh-CN.md`。

**本任务不是 G33 产品实现授权。**它只负责在任何源码、cargo、CLI 或浏览器执行之前，确定下一项用户目标和可验收合同。

## 1. 冻结

以下内容只读：

- G32 推荐包 `g32-camera-pan-3-layout-1`；
- G32-R2-C1 全部证据、manifest、receipt、截图；
- G31-R1 基线；
- G32/R2-C1 产品源码和构建产物。

本闸门不得修改产品源码、旧包、旧报告或旧清单，不得启动 cargo、CLI、浏览器，不得生成新的产品包。

## 2. 必须写定的 G33 输入

在获得实现授权前，先写 `g33-scope.zh-CN.md`，至少包含：

1. 一个明确的用户可见目标；
2. 与 G32 的边界：哪些交互/渲染/模型/工程能力保持冻结；
3. 明确不做的内容：不得把 ST18、默认世界、自然生成、route/bake/realize、工程安全或发布能力默认为本轮范围；
4. 成功与失败判定；
5. 必须真实浏览器验证的场景；
6. 可离线证明的纯函数和结构合同；
7. 需要的 cargo/CLI/browser/aux/归档额度；
8. 预算耗尽、真实产品失败和驱动失败的停止规则；
9. G32 基线包的 hash、生产 ID 与只读绑定；
10. 是否需要新的视觉 intent 与基线截图。

## 3. 闸门输出

只有以下文件完成后，才能讨论 G33 实现任务：

- `g33-scope.zh-CN.md`；
- `g33-baseline-binding.json`；
- `g33-budget-proposal.json`；
- `g33-stop-rules.zh-CN.md`。

这些文件只能描述范围和计划，不得声称 G33 已实现、已构建或已验收。

## 4. 下一步裁定

在用户确认 G33 目标和预算前：

- G32 维持 `accepted_scoped_with_process_exceptions`；
- G33 保持 `not_started`；
- 不运行任何产品进程；
- 不追加 G32 复测；
- 不以 G32 证据替代 G33 证据。
