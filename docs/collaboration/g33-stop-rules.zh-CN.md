# G33 停止规则

日期：2026-09-28（北京时间）。
依据：`handoff-g32-g33.zh-CN.md`、`b01-g32-final-verdict.zh-CN.md`、`dsh-b01-g33-scope-gate-task.zh-CN.md`。
状态：**G33 = `not_started`**。本文件只定义停止规则，不构成实现授权。
配套：`g33-scope.zh-CN.md`、`g33-baseline-binding.json`、`g33-budget-proposal.json`。

## 0. 总则

任何类别余额不足时，**不得启动**对应进程；不允许先运行、后只作披露。
纯读取、哈希、目录枚举、文档/manifest 编排属于管理日志，不消耗产品额度。
每个成功 / 失败 / 参数拒绝的进程都入台账。

## 1. 三类停止，分开判定

### 1.1 预算耗尽

- 触发：任一类别（cargo / CLI / browser / aux）达到其上限。
- 处理：立即停止该类别，交当前准确状态。
- 禁止：用历史余额抵消今日超支；把超支事后合法化；为凑绿而无限追加。

### 1.2 真实产品失败

- 触发：在真实浏览器/真实数据上出现产品缺陷
  （小地图与 pan 语义不一致、footprint 错误、劫持旋转/缩放/拾取、
  布局或几何回归、GL/console/page 错误计数非 0）。
- 处理：停止扩展范围；交准确 partial；保留失败证据；
  保持 G32 基线只读；不进入下一轮，除非有新用户目标。
- 禁止：把真实产品失败归因成驱动失败以规避结论。

### 1.3 驱动 / 夹具失败

- 触发：断言写错、用了过期矩形、点在画布外、夹具时序错误、
  stub 失真，导致结论无法成立或与产品无关。
- 处理：如实披露；把该项记成驱动失败（或未观测），
  **不得**改写成产品失败，也**不得**改夹具后直接声称通过。
- 允许：一次带明确目标的复测，用于把驱动失败转成可判定；在此之前不得把该项记成通过。

## 2. 证据口径（不得违反）

- 严格区分：离线纯函数 / VM fixture、真实 Chrome 鼠标键盘操作、
  `page.evaluate` 受控事件、只读 DOM 探针、历史引用。
- **禁止**用离线 fixture 冒充浏览器；**禁止**用只读探针冒充正式交付会话；
  **禁止**用旧截图证明新产品修改；**禁止**用报告文字替代原始记录；
  **禁止**用 manifest/receipt 绑定替代产品行为证明；
  **禁止**用 `pickMethod` 这个输入来源常量冒充求交算法证明。
- 未观测项必须单列，不得用“已解释”冒充“已观测”。

## 3. 交付口径

- 成功只交 `delivered_for_inspection`，**不自宣通过**；最终接受由独立审核方裁定。
- 失败交准确 partial，并区分产品失败 / 驱动失败 / 未观测。
- 未获得 G33 实现授权前：不运行 cargo / CLI / 浏览器；
  不追加 G32 复测；不以 G32 证据替代 G33 证据；
  不在没有新任务书时扩大产品白名单；
  不把旧证据回写或改写。

## 4. 归档与绑定顺序

最后顺序固定为：

```
raw records
→ report / facts / budget / command log
→ manifest（最后枚举绑定文件）
→ receipt / delivery
→ independent read-only verification
→ final verdict
```

manifest 必须最后枚举绑定文件；不能用事后文档排除绑定范围。
封存交付后任何补充都放到新目录，不把 post-manifest 文档当作新的排除权。

## 5. 资源纪律（来自交接 §6）

- 报预算超出必须单列，不用历史余额抵消，不事后合法化；
- 允许追加**一次**有明确目标的复测，但禁止无限微调到绿色；
- 一次失败后先区分产品问题、驱动问题、证据缺失，再决定是否申请资源；
- 不以更多资源替代清晰的合同与停止规则，也不因过去的额度纪律问题让必要的低风险复测被饿死。
