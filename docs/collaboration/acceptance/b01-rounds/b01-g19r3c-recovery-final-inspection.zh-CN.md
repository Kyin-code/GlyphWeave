## 2. P1：事件区间存在平面覆盖就跳过，忽略层与净宽

G:/difyllmwiki/GlyphWeave/bevy/crates/core/src/worldgen/engineering_connections.rs约3451–3455行：

    if frames.iter().any(|frame| frame.contains(at.x, at.z, tolerance)) {
        continue;
    }

MemberFrame::contains只检查x/z平面轮廓。当前事件区间只在“没有任意frame平面覆盖”时测有效层带宽，因而引入两类错误：

1. 另一高度的无关部件会跳过有效层缺口检查。
2. 中心线有支持、但两侧不足宽的部件，也会跳过事件区间带宽检查。

这是与报告“每个事件区间必须被真实支持覆盖”不等价的实现，不是斜交特殊性或新增设施需求。

## 3. 当前折返几何失败成立，但“只有A/B两条合同出路”未证

### 可接受的局部事实

- 当前生成器把梯段与转向平台按现有规则放置，产生实测实体重叠；拒绝是当前规则的实际行为。
- current positive-terrace也包含同一个折返结构，因构建全场景先失败而无法检验直跑路线。不能据此说独立直跑楼梯也必然无合法构造。
- 对固定梯段终止线与固定转向走线的分析，可解释当前方案为何受阻；不能扩大到所有合法部件划分、平台内部走线、接续端口或生成算法。
- deck-platform悬挑问题保持“推导、尚未越过先前失败实测”的标签。

### 不采纳的结论与方案

- 不采纳“折返楼梯在安全合同下无自洽几何”的全称结论。本包没有枚举或证明全部允许布局/构件分解方式，且事件判据本身尚未可靠。
- 不采纳A所述“同层行走构件自动不计互穿”。同高度、同owner或角色标签均不能成为实体碰撞豁免；尤其不能把riser、无关平台、墙柱一起当作可行走连续面。
- 不把B当唯一后路。应优先区分**安全要求**（不穿实体、有效承托、宽度/层高/能力）和**生成器自定几何约束**（梯段起止/平台中心/转向线/端口布局）。修正后一类不必等于放宽前一类。
- “检查员钉死所有端口坐标集”不准确。固定的是检查员反例输入及其预期；前续作明确允许合法fixture有依据的几何修订并保留差异。若改动外部接口或放宽合同，仍需另行授权，但不能把任一内部接续点都当成永远不许改变。

### 推荐的工程方向（不是已证明的最终解，也不构成执行授权）

一个明确描述的折返构件应当先有自洽的剖面/平面定义：梯段结束处、平台实体范围、实际转弯折线、第二梯段起步处、接续端口以及支撑关系由同一几何模型生成。

优先研究实体不重叠的部件分割/裁切和平台内部有净宽余量的转向路径；若同一结构确实需要合并成一体，应显式生成唯一实体与来源关系，而不是在碰撞检查时忽略重复体积。该方向须另批评估和实现，不声称已经有合法正例。

将最小直跑、最小折返、平台、挖填及独立审核测试分开，再保留整合场景。这样一个折返前置失败不会把所有发布/篡改/坡度测试全部遮住。不能删除原红测或降低预期，仅新增隔离验证与明确保留整合阻断。
