# V41F 自主权章程（长期有效）

日期：2026-09-30。签发：检查员/项目经理 Claude，依据项目负责人“保留自主性、减少询问”的指示。
效力：自本文件起对所有后续任务书生效；与旧任务书中的“停下交检查员裁定”“等待放行文件”“超过 N 个就停”等条款冲突时，**以本章程为准**。

## 1. 原则

事前把关只留给**无法撤回**的事；其余一律**先做、记录、事后审**。你手里的数据比检查员多，设计取舍由你决定。

## 2. 你可以自行决定、不必询问的事

- 在多个修复方案之间选择，包括改变内部算法、数据结构、调用顺序、几何/记账口径；
- 修改 `bevy/crates/**` 下任何生产代码与测试代码，只要与当前任务目标相关（不再按文件白名单授权）；
- 发现任务书的假设或建议是错的：按数据走，在决策日志里写明推翻的依据；
- 新增诊断测试、临时探针（交付前删除）；
- 在额度池内安排世界运行、审计、预览的时机；
- 跨多个会话接力，直到达到任务目标；
- 判断某个站点/对象被合法拒绝是否可接受（写明数值）。

## 3. 底线（碰到才停下报告；只有这些）

1. Git 写操作（提交、切换、回退、stash、推送）；
2. 修改或删除历史证据目录（已冻结的世界、旧轮证据、b8 等）；修改 `F:\modenmapbox`；
3. 修改项目负责人定下的输入：manifest 的需求数量、zoning、保留区、保护区、水域、场景尺寸、城乡比例、seed；
4. 调低任何**数值合同**的严格程度（坡度、填方上限、走廊宽度、退界、审计精度、容差），或删除/忽略/削弱既有测试断言；
5. 6×10km 世界；参数扫描式地消耗世界额度；
6. 额度池耗尽。

说明第 4 条：改变“某个量怎么算、归到哪一类”属于设计决定，你可以做；但把一个数字阈值调松、把失败改名成通过，不可以。拿不准时的判据：**改完之后，一个真实存在的缺陷是否更难被发现？** 是，则属于底线。

## 4. 你必须保持的三条纪律

1. **决策日志** `decisions.jsonl`：每个非显然的取舍一行——问题、备选、选择、依据（数据文件/数值）、可撤回方式。这是事后审查的主要材料。
2. **状态不粉饰**：绿测 ≠ 达标；未观测就写未观测；回归就写回归。
3. **世界运行前写一句预期**（一行即可，写进 `runs.jsonl`）：这次预期哪几个数变好。运行后对照。不再需要独立的预注册文件、自检文件、放行文件。

## 5. 精简后的交付物

每个任务只需：`checkpoint.json`（随做随更新）、`runs.jsonl`（命令、exit、日志路径）、`decisions.jsonl`、结束时一份 `report.json`（结果、数字、未完成项、源码全集 hash）。
不再要求：逐轮写集、逐文件起止 hash、突变日志逐条归档、预注册/自检/放行文件。关键不变式用**测试**守住，而不是用文书守住。

## 6. 什么时候回来找检查员

- 达到任务目标；
- 碰到第 3 节底线；
- 额度池用完仍未达标。

除此之外不必回来。上下文耗尽：写 checkpoint，新会话继续。

## 7. 上下文纪律（保留）

大文件只按 `grep -n` + 行号范围读取（每次 ≤120 行）；cargo 输出重定向到日志只读结果行；JSON 用脚本抽字段。
