# 自然—聚落—市场演化 W1/W2/W4/W5 实现记录

日期：2026-10-21

状态：**第一版中型实现已实烘焙并通过 scale audit / quality report；继续处理入口遗漏与新旧城深化**

## 1. 已确认的审核口径

项目负责人已确认：

1. 每个正式城市保留冻结自然基线，先完成无人类痕迹的自然世界；
2. 普通建筑取消固定完成数，推荐数只用于密度核对；
3. 建筑尺寸由地块、用途和地形推导，允许为地形更新模型；
4. 新旧城区使用同一骨架的多阶段迭代；
5. 中心性来自真实网络，而不是地图圆心；
6. 生鲜市场使用多层级、容量、时距和竞争；
7. 48 城用于特征机制与少量代表切面复刻，不追求统计全场；
8. 工程数据保留弱门限；特征地区、绝对中央城区、横琴/东沙式造岛等宏观工程
   服从规划与合理性，不把普通地块的弱门限当作绝对禁令。

本记录只声明已经实际生成、保存和审计的能力。未完成项在 §6 明列。

## 2. 本轮新增能力

### 2.1 自然基线冻结与最终差分

新增 `worldgen/natural_baseline.rs`：

- 在任何道路、建筑或工程计划之前冻结自然高度场；
- 保存自然高度哈希、自然控制哈希、格网数、阶段和零人工痕计数；
- 最终 bake 后逐格比较自然与最终高度；
- 拒绝场景不同、缺失分块、自然栅格在冻结后被改写的基线；
- 输出 `natural-baseline.json` 与 `natural-final-diff.json`。

### 2.2 自然节点选路

`route_evolution` 新增：

- 从 1m 高度场按 64m 搜索步长提取干地自然节点；
- 节点记录高程、坡度、平坦度、谷地分数、接近水体程度和综合分数；
- 自动锚点从四个象限选择自然节点；
- 自动道路请求由锚点最小生成树形成多段网络，而不是单一直线；
- 道路继续经过坡度、纵坡、水体、桥涵和填方合同。

### 2.3 需求—地块—建筑原型

新增 `settlement/building_archetypes.rs`：

- 原型覆盖町家、欧洲周边街区、美国独立住宅、中国封闭小区、城中村、
  香港屋邨、中层公寓、街面商业和办公塔；
- 原型给出面宽、进深、层数、覆盖率与推荐数范围；
- 实际建筑楼层由中心压力、地块尺寸和需求共同决定；
- 住宅原型在高密度时升级为 `residential_block` / `residential_tower`，
  商业原型在高密度时升级为 `urban_building`；
- 地块新增到道路站点的连接点和显式短引道；
- 道路与自然地面的高差超过 `accessHeightToleranceM` 时拒绝该地块，
  不再把山坡高位道路直接当成谷地住宅入口。

普通建筑仍然没有固定完成数。`recommendedCount` 仅写进计划，供密度审计使用。

### 2.4 分级生鲜市场

`market_catchment` 新增层级：

- `street-market` / 社区菜场；
- `neighbourhood` / 邻里超市；
- `district` / 大型超市；
- 保留向后兼容的单一市场回退；
- 每层独立配置容量、服务质量、最大时距、数量、候选间距和偏好；
- 选择时同时考虑未满足需求、网络时距和层级偏好；
- 最终负载按容量竞争分摊，市场负载不得超过容量；
- 市场计划转换为实际静态 `market` 实体。

### 2.5 入口和访问修复

本轮定位并修复一个长期入口问题：

- 搜索路径时原先把建筑自身也作为障碍物，导致从建筑立面出发的路线
  立即被自身 footprint 阻挡；
- 现在入口短段仍排除自身，但公共路径搜索同样排除当前建筑；
- 建筑 pad 从 footprint 最高自然点建立平台，入口锚点与短引道使用同一
  平台高度；
- 未通过严格入口合同的建筑仍具名保留在 materialization report；
- 计划引道、建筑和访问图共享同一最终地形。

### 2.6 特征切面的宏观工程授权

普通地块与道路继续保留 6m 填方、8% 纵坡、25% 步行坡和 2m 地块削方
弱门限。`routeEvolution.maxFillM > 6` 只有声明
`urbanSlice.mode = "feature-cut"` 时才允许。

`engineering-scale-plan.json` 新增 `macroAuthority`：

- 记录切面模式、主体特征、特殊因子、允许上限和理由；
- 普通道路仍标为 `approved-within-local-fill-contract`；
- 特征切面超过 6m 的工程标为 `approved-macro-authority`；
- 未授权世界仍以 `rejected-local-fill-contract` 失败；
- 局部合同对象不被改写，宏观工程只能通过独立账本扩大规模。

## 3. 1km 实烘焙候选

Manifest：

`examples/natural-evolution-core-city-1km.manifest.json`

输出：

`bevy/work/rk-x/v3-w1w5-natural-evolution-1km-final16/`

世界参数：

- 场景：1000m × 1000m，seed 42；
- 自然：山地湖谷派生地理；
- 道路：无手写锚点、无手写路线，自动从自然节点形成 3 条道路；
- 聚落需求：800 户、700 岗位、8000m² 商业、20 服务单位；
- 市场：3 层，最多 8 个市场；

## 5. 当前判断

- “先自然、后道路、再聚落”已经在同一 bake 中成立；
- 建筑数不再由固定 count 补齐，而是需求和地块容量的结果；
- 建筑体量因社区原型、中心压力和层数发生分化；
- 中心由道路网络中心、角色和可达性共同生成；
- 市场已从单一容量点变成分层实体和网络覆盖；
- 工程改造可回到冻结自然基线逐格核对；
- 预览尚未作为最终视觉验收，下一步必须检查实际画面是否有空置、
  错接、道路消失、建筑入口断裂和非预期孤立引道。

## 6. 仍未完成

1. 23 个计划建筑中仍有 11 个未通过最终入口合同，主要原因是坡地入口台阶工程；
   入口锚点边界误差已经修复；
   所有失败已具名进入报告，但最终核心区建筑数量仍偏低。
2. 市场计划 5 个，最终保留 3 个；需要继续让市场占地和入口像普通建筑一样
   进入同一条严格入口链。
3. 新旧城已经按中心距离采用不同地块尺度和原型；本控制中 23 个计划为
   2 个旧城窄街屋和 21 个更新带地块。新区原型已经实现，但本轮需求在
   更新带已经满足，未继续生成新区建筑；后续需要按切面声明分配跨区需求。
4. 48 城的少量特征切面尚未逐一烘焙；当前是机器先验加一个合成核心切面。
5. 宏观开山、填海、造岛仍需要独立工程账本和规划授权区；本轮只修复普通
   道路/地块的过渡环，不声称特种工程授权已完成。
6. HTML 预览需要基于本候选重新启动并做视觉反馈；不能以 scale/quality
   pass 代替视觉通过。

### 6.1 后续实现顺序

5. 重新生成战略图、街景、自然视图和市场辐射图，提交
   `visual-feedback.json` 后再宣布视觉层完成。
