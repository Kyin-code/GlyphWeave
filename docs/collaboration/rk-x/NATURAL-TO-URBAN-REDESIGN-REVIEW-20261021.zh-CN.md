# 自然地貌到现代城市：生成链重构审核稿

状态：**待项目负责人审核；审核通过后才按 P0 → P7 继续实现**

日期：2026-10-21

审核入口：先读 §0、§4、§14–§18；§19 区分“当前已有脚手架”和“尚未交付”。

## 0. 结论

现有生成链的问题是顺序和语义错误，不是楼房模型不够多：

1. 当前道路先由固定网格选出基础边，再围绕道路生成 frontage；
2. frontage 请求显式写建筑 `count`，容易把“需求”变成“必须凑数”；
3. 中心距离目前接近圆心裁切，不能表达可达性、商业竞争和历史阶段；
4. 聚落没有先从水源、谷口、渡口、可建设地和道路交汇中自然出现；
5. 新老城差异仍偏“同一套地块 + cohort 材质”，不是保留、填充和更新的过程。

建议的新主链：

```text
Manifest 地理背景
→ G0 区域地质/气候/水系/地貌
→ N0 纯自然世界
→ 人类初步路径
→ 沿谷/梁/渡口形成道路工程
→ 聚落种子涌现
→ 按城市规模选择整城或核心切面
→ 旧核心生长
→ 扩张与工业化
→ 现代新区/更新区
→ 功能设施与生鲜市场服务场
→ 联合审计与完整烘焙
```

目标是生成“经历多个建设阶段后的静态结果”，不是完整人口/经济史模拟。

## 3. 跨样本抽取的七条逻辑

1. 交通与自然先于建筑；建筑是可达地块的后续填充。
2. 建筑数量是需求、地块容量和约束的结果，不是预设完成数。
3. 中心不是唯一圆心；轨道站、市场、教堂/寺庙、学校、港口和桥头也可以是次级中心。
4. 老城不是低质新城：老城保留细街网、小地块、混合底商和历史节点。
5. 郊区、旅游、放牧、种植不是低密城市，各自有道路、地块和设施逻辑。
6. 商业是网络：底商、便利店、菜场、超市、批发与旅游商业服务不同人群与容量。
7. 更新必须是保留、拆合、填充、重建的显式操作，不能用材质换新旧。

## 4. 新生成编排

### N0 自然世界

输出地质、地貌、山脊谷地、坡度、曲率、河流湖泊、湿地海岸、水位流向、土壤、
气候、生态群落、灾害与资源。此时没有道路、建筑、农田或人工构筑。

闸门：

- `humanTraceCount = 0`；
- 高度、水面、岸线和 chunk 边界连续；
- 同一 seed 重复得到相同自然快照；
- 通过战略图和自然近景验收后才进入下一阶段。

### H1 人类初步路径

从谷口、渡口、山坳、泉水、湖岸、海岬、林缘、农地和资源点建立候选节点。
路径使用有曲率的地形成本搜索，代价包括坡度、转弯、水深、湿地、林地、侵蚀、
洪泛和桥隧成本。

道路不以直线为默认；能沿谷线、等高线或山梁时优先顺应地形。过水必须有桥梁、
堤道或涵洞结构，或者明确拒绝。

### H2 道路网络和地形工程

- 区域连接/港口/铁路/城市核心产生 arterial/collector；
- 聚落内部产生 local/alley/path；
- 农田、牧场、林场有各自道路类型；
- 路口通过显式端点和真实交汇几何连接；
- cut/fill/bridge/culvert 都作为有版本的工程操作。

### S1 聚落种子

聚落数量不预设，由以下分数决定：

- 水源可靠性和洪水风险；
- 可建设面积、坡度、排水；
- 渡口、桥头、港口、道路交汇；
- 土壤、牧场、木材和资源；
- 风景、交通、防御和与既有聚落的互补。

未达到可建设/接入阈值的候选只进入拒绝报告，不生成“凑数小屋”。

### S2 建筑涌现

```text
住户/就业/服务需求 + 地形和地块容量
→ 用途和强度预算
→ 地块拆分和可建面积
→ 建筑类型、体量、入口
→ 实际建筑数量（结果）
```

普通建筑不再要求“每个请求必须完成 N 栋”。`householdsTarget`、就业岗位、
商业面积或摊位容量是需求；建筑数量是容量与地块条件的结果。

不能满足时输出 `unmetDemand`、原因和替代候选，不复制建筑、不缩小合同塞入。
固定数量只用于明确地标或明确必需设施，并且仍需通过空间合同。

### S3 建设阶段与新老城

| epoch | 典型空间结果 |
|---|---|
| founding | 渡口/路口/寺社/市场旁的小聚落，窄路小块、混合使用 |
| old-core | 细街网、连续街墙、小店铺、市场/教堂/市政/老宅 |
| expansion | 沿谷/道路扩展，学校、住宅组团、铁路/仓储 |
| industrial | 铁路、仓库、厂房、工人住区、缓冲带 |
| modern-new | 站点/快速路周边，大块地、写字楼、塔楼、超市和公园 |
| renewal | 保留部分旧路和建筑，拆合地块，加入新用途与公共空间 |

每个对象保存 `constructionCohort`、父对象、保留/修改/拆除/新建操作和来源。
新老城是旧骨架经过阶段更新的结果，不是两个模板拼接。

## 6. 生鲜市场辐射模型

### 设施层级

- 社区菜场/湿货市场：老核心、住宅街区，摊位/营业面积为容量；
- 邻里超市：普通城区和站城混合区，建筑面积/冷藏能力为容量；
- 大型超市：新区/郊区走廊，停车和配送纳入约束；
- 周期性市场：乡村旅游/广场，记录开放时段；
- 批发/集散市场：城市边缘、铁路/港口，服务农业生产和物流。

### 公式

对需求单元 `i` 和设施 `j`：

```text
吸引力 A_ij = capacity_j * quality_j * exp(-beta_mode * travel_time_ij)
需求分摊 P_ij = A_ij / Σ_k A_ik
设施负载 L_j = Σ_i demand_i * P_ij
局部供给密度 rho_i = Σ_j capacity_j * exp(-beta_mode * travel_time_ij)
缺口 deficit_i = max(0, demand_i - rho_i)
```

- `travel_time_ij` 从真实步行/道路/公交网络计算，不用直线距离；
- 步行、骑行、车行、公交使用不同衰减参数；
- 市场之间通过分母竞争，重叠服务自动降低边际价值；
- 每次放置后重算负载，防止市场互相挤死；
- 不满足最低需求的候选不放置，记录 `under_minimum_demand`。

初始启发式范围：

- 高密旧核心：步行 5–10 分钟，网络距离约 300–700m；
- 普通城区：步行 10–15 分钟，约 600–1000m；
- 新区/郊区：以邻里中心和 10–15 分钟公交/车行为主；
- 乡村：周期/集散设施按 3–8km 车行和人口阈值；
- 旅游区：居民与游客需求叠加，不能只看常住人口。

这些是待标定参数，必须保留“网络时间 + 容量 + 竞争 + 需求”的模型结构。

## 9. 分阶段实施计划

### Phase 0 纯自然

冻结自然快照，0 人类实体，完成地形/水系/生态/chunk 连续审计。

### Phase 1 自然道路

自然种子生成非直线道路；记录曲线半径、断面、桥梁/涵洞；与旧网格做 A/B。

### Phase 2 聚落涌现

聚落数量由水源、可建设面积和道路接入决定；允许 0 个，禁止凑数建筑。

### Phase 3 容量建筑

按住户、就业、商业面积和地块容量生成；建筑数量成为结果；缺额具名持久化。

### Phase 4 新老城

依次执行 founding/old-core/expansion/industrial/modern-new/renewal；记录保留、
拆合、填充和新建操作。

### Phase 5 场景与市场

郊区、旅游、放牧、种植分别使用独立规则；市场按服务场和容量布局，生成
辐射密度诊断图。

### Phase 6 全链验收

- 自然图、战略图、旧城/新城近景、市场辐射图分别截图；
- 跨块道路/水岸/聚落连续；
- 入口可达、地面贴合、水体和保护区不破约；
- 每个阶段有独立 hash；
- `quality-report warn` 不得被解释为视觉完成。

Agent 输出的是地理意图与参数范围；Rust 负责生成不可变的自然快照：


必须有独立的 `natural-geography-plan.json` 和 `natural-only` 审计。河流改道不是装饰：
旧河道保留为低地、牛轭湖、冲积土或湿地，当前河道再在其上叠加。海沟、造山、
风蚀和喀斯特只在 Manifest 声明的地理背景允许范围内出现。

## 14. 城市切面语义

### 14.1 城市规模与表达方式

| settlementScale | 典型人口/角色 | 生成方式 |
|---|---|---|
| `village` | 数百人、农业/牧业/旅游小点 | 可完整生成村落与田块 |
| `town` | 数千至数万、独立县域服务 | 可完整生成镇区与外围 |
| `county-city` | 十万级、县域中心 | 生成完整主城切面 + 周边关系 |
| `city` | 百万级、多个片区 | 生成城市中心/新区/郊外关系图，不伪称全城 |
| `metropolis` | 数百万至千万级 | 生成核心切面及跨边界交通/水系上下文 |
| `megacity` | 千万级都市圈 | 只生成有主题的地理切面，如湾区、老城、行政中心 |

Manifest 必须在 `style.urbanSlice` 声明：

```json
{
  "style": {
    "urbanSlice": {
      "version": 1,
      "settlementScale": "metropolis",
      "mode": "feature-cut",
      "focusFeature": "bay-waterfront",
      "cropReason": "represent the port-city relation rather than whole metropolis",
      "contextRadiusM": 2500,
      "offMapContinuity": ["roads", "rail", "river", "urban-fabric", "coast"],
      "specialFactors": [
        "financial-center",
        "coastal-reclamation",
        "special-economic-zone"
      ]
    }
  }
}
```

切面不是随便裁一块地图：

- 大都市切面必须围绕一个可解释特征（湖、湾、政治轴、老城、港口、科技园区）；
- 边缘道路/河流/轨道必须带“来自场外”的接入意图，不在地图边界伪造终点；
- 切面内部应包含该特征所需的城市关系，而不是铺满同一种住宅；
- 小县城才允许完整展开行政边界和外围田/牧场。

### 14.2 切面识别

从语义或 Manifest 选择：

1. 地标/特征：西湖、白宫、深圳湾、老城、港口、高铁站；
2. 关系：山—湖—城、江—岛—城、行政轴—住区、港口—物流—城市；
3. 规模：大都市切面、城市全区、县城全貌、村落；
4. 时间：建国前核心、工业扩张、现代新区、更新区；
5. 约束：海岸/山体/历史保护/生态敏感；
6. 可见参照物：桥、塔、街区、站、岸线或公共建筑。

切面选择应产生 `sliceFocalPoint`、`contextRadiusM`、`offMapConnections` 和
`requiredFeatureRelations`，下游生成必须围绕这些关系组织，而不是先把整张图
均匀铺满。

## 15. 规划史与城市迭代

48 城共同说明：城市不是一次性生成，而是叠层：

```text
自然基底
→ 原始路径与水工
→ 历史核心
→ 工业化/铁路/港口
→ 战后住宅/郊区化
→ 高速/轨道/新区
→ 城市更新/遗产保护/生态修复
```

### 区域差异

| 区域 | 常见街区/社区结构 | 更新特征 |
|---|---|---|
| 中国 | 单位大院、封闭小区、城中村、超大街区、轨道新区 | 旧城保护、城中村更新、新区扩张、工业退二进三 |
| 美国 | 网格/细分住宅区、商业带、停车广场、收入分层社区 | 高速城市更新、滨水再开发、公交导向填充 |
| 欧洲 | 连续街墙、庭院街区、公共住房、历史核心、绿带 | 工业遗址更新、轨道站点、历史保护与填充 |
| 日本 | 细地块、町家/商店街、轨道站、住宅团地 | 震后重建、站城更新、城市防灾 |
| 香港 | 高密街区、公共屋邨、填海、垂直混合 | 工业转型、旧区重建、海滨公共化 |

### 规划迭代规则

- 旧路网优先保留；新建道路必须解释为连接、拓宽、绕行或更新；
- 拆迁移除必须记录 `preserve/replace/demolish` 与父 ID；
- 公园可从旧河道、铁路废线、工业地块、山脚和更新空地中产生；
- 金融/政治中心依赖中心性、可达性和历史/行政角色，不能只按地图几何中心；
- 同一地块可有多个使用单元和入口，不强制“一栋楼一个 kind”；
- 新城可以规划网格，但网格必须服从地形、保护地和区域连接。

## 16. 土地紧张度与工程强度

### 16.1 土地紧张度

建议用一个连续场而不是单一城市标签：

```text
landPressure_i =
  settlementScaleFactor
  * regionalDemand
  * exp(-networkDistanceToCentre / gravityScale)
  * terrainScarcity
  * protectionMultiplier
  * specialRegimeFactor
```

- `settlementScaleFactor`：小县 0.25–0.45；城市 0.45–0.75；大都市核心 0.75–1.2；
  超大都市核心 1.0–1.5；
- `terrainScarcity`：平原 1.0；丘陵 1.15–1.35；山地/岛湾 1.35–1.6；
- `protectionMultiplier`：生态/历史保护区提高绕避成本，但降低可施工强度；
- `specialRegimeFactor`：特区开发 1.2–1.4；旅游区按季节和生态约束单独定义；
  重庆类山地额外提高台地/桥隧权重，不提高任意挖山许可。

### 16.2 工程动作分级

| 规模 | 允许动作 | 不可越过的底线 |
|---|---|---|
| 建筑/pad | 有界削填、挡墙、台阶、入口引道 | 既有 2m pad cut cap、入口 2m apron、25% walkable |
| 道路 | 纵坡 profile、削填、挡墙、桥/涵洞、绕行 | 6m 填方、8% 纵坡、水体/岸线零非法土方 |
| 城市片区 | 关停/拆除/填方、海堤、台地、河道治理、公园更新 | 必须显式工程操作、来源、体积、排水/生态审计 |
| 特殊工程 | 大坝、深挖、填海、隧道、轨交 | 需城市规模/特区/旅游/山地因子和独立审批，不从视觉自动放行 |

大都市核心的土地紧张会提高：

- 轨道/桥/隧道与多层公共空间；
- 滨水填海、码头、海堤和抬高地坪的候选权重；
- 山城台地、挡墙和盘山路；
- 旧城拆合、地下停车/轨交和公共空间回收；
- 市场/服务的小型化和垂直分层。

但土地紧张只改变候选、造价和工程类型，不会自动合法化超过局部硬约束的
建筑垫层。宏观工程通过显式 `EngineeringOperation` 另立预算、体积和审计。

|---|---|---|
| P0 | Manifest 地理背景 + `natural-geography-plan.json` + 纯自然 world | 无人类痕迹；地质/气候/水系/地貌参数可追溯 |

## 18. 本轮补充后的审核问题

1. Manifest 是否要求作者至少写出大地理环境，而不是只给 seed？
2. 大都市是否默认只生成“特征切面”，小县城才默认整城？
3. 普通建筑数量是否彻底改为容量/需求结果？
4. 是否接受局部建筑 pad 仍保持现有硬约束，而宏观工程以独立项目放开规模？
5. 48 城的地理/历史表是否作为参数先验，而不是逐城固定脚本？

## 19. 批准后的修改编排

本节是审核通过后的执行清单。每个阶段都必须先产出机器可读计划/审计，再允许
下游阶段读取；前一阶段失败时不能靠渲染或补丁掩盖。

### P0 纯自然快照

修改范围：

- `worldgen/natural_geography.rs`：地理背景 → 确定性自然控制；
- `worldgen/natural_only.rs`：人工实体白名单之外的任何道路、建筑、桥梁、
  农林设施、市场、学校、教堂都具名失败；
- `worldgen.rs`：在道路/聚落规划之前冻结自然快照及阶段 hash；
- 示例 Manifest 与 48 城机器可读先验。

必须输出：

- `natural-geography-plan.json`：造山、海岸、气候、季风、风蚀、喀斯特、冰川、
  旧河道、湿地和灾害控制；
- `natural-world.json`：山脊/谷地/盆地/阶地、分水岭、河流/湖泊/海岸、水位、
  土壤、生态群落、灾害和资源；
- `natural-audit.json`：`humanTraceCount=0`、禁生成实体明细、水面/岸线/分块
  连续性、确定性 hash。

验收：

- 同一 seed 两次生成逐字节一致；
- 自然阶段截图只有地形、水体、植被、岩石、湿地等自然内容；
- 旧世界不声明 `naturalGeography` 时保持既有语义，不能被静默改写；
- 至少一个山地湖谷样例和一个平坦三角洲样例证明地貌不是同一套噪声换色。

### P1 地形路径与道路

修改范围：

- 新增 `route_evolution.rs`：从谷口、渡口、山坳、湖岸、海岬、资源点和既有
  聚落建立种子；
- 在自然高度、坡度、曲率、水系、湿地、灾害与建造成本场上做有曲率路径搜索；
- 道路实体增加可审计 `polyline`、曲线半径、宽度、纵坡和贴地采样；
- 过水必须选择桥、堤道、涵洞或具名拒绝；
- HTML 只读取烘焙后的道路带和控制点，不再把道路画成固定轴网。

必须输出 `route-evolution-plan.json` 和 `road-alignment-audit.json`。验收重点是
“沿谷/沿等高线/绕避湿地”的因果，不是简单让线段抖动；道路仍受 6m 填方、
8% 纵坡、岸线净距和跨块连续性约束。

### P2 聚落种子与城市切面

修改范围：

- 新增 `settlement_seed.rs`，以水源、洪水、可建地、接入、资源和互补性评分；
- `urban_slice.rs` 决定整城、片区切面或特征切面；
- 大都市、超大都市禁止声称生成完整城市；
- 入口/港口/站场/桥头等场外连接保留方向与容量，不能在地图边界假装终点。

必须允许聚落数量为 0 或低于候选数，并输出每个候选的接受/拒绝原因。示例：
山地湖湾用“山—湖—旧城—新区—郊外”切面，而不是把 1km 均匀铺满住宅。

### P3 需求、容量与建筑数量

修改范围：

- 新增 `development_demand.rs` 与 `parcel_capacity.rs`；
- `householdsTarget`、`jobsTarget`、`retailFloorAreaM2`、`serviceBudget` 是需求，
  不是建筑完成数；
- 地块按可建面积、退界、入口、日照/消防/地形和规划用途计算容量；
- `frontageProgram.requests.count` 只保留给显式地标或法定指定设施；
- 输出 `unmetDemand`、拒绝原因和替补候选。

验收必须证明建筑数量随需求、地块容量和约束变化，而不是因为请求写了 N 就
复制 N 栋；不得通过缩小建筑、压缩入口或放宽硬合同“完成”需求。

### P4 建设阶段与新旧城

修改范围：

- 新增 `epoch.rs`，按 `founding → old-core → expansion → industrial →
  modern-new → renewal` 顺序演进；
- 每个对象保存父 ID、`constructionCohort` 和 `preserve/modify/demolish/new`
  操作；
- 旧路、地块边界、历史建筑和公共空间可以保留；新路必须是连接、拓宽、绕行
  或更新；
- 公园可从旧河道、废铁路、工业地块、山脚和更新空地产生。

中国单位大院、封闭小区、城中村、轨道新区，美国细分住宅、商业带、停车与
收入分层社区，欧洲庭院街区/公共住房，日本细地块/站城，香港屋邨/垂直混合/
填海，都由功能规则和 epoch 组合产生，不靠材质换色。

### P5 功能布局与生鲜市场辐射

修改范围：

- 新增 `functional_area.rs`：旧核心、普通城区、新城、郊区、旅游、放牧、
  种植和保护区；
- 写字楼、住宅、商超、学校、医院、教堂/寺社、市场由需求、cohort、中心性、
  地块容量和可达性决定；
- 新增 `market_catchment.rs`，在真实步行/道路/公交图上计算容量、旅行时间、
  竞争、负载、局部供给密度和缺口；
- 输出市场服务场与 `deficit_i` 诊断图。

验收不能只看“附近有没有一个市场”，还要看旧城与新区、居民与游客、常住人口
与季节性需求是否得到不同辐射结果。

### P6 土地紧张与宏观工程

修改范围：

- 把 `landPressureIndex` 从整图系数扩展为“中心性 + 可达性 + 地形稀缺 +
  保护 + 城市/特区/旅游/山地因子”的连续场；
- 宏观填海、挖山、台地、桥隧、轨道、堤坝和河道治理都生成显式
  `EngineeringOperation`；
- 每项操作记录 footprint、体积、自然场版本、目标标高、排水、灾害、生态影响
  和审计状态。

城市规模决定候选和预算，不自动放宽局部硬合同。大都市核心可以更倾向轨道、
桥隧、台地、填海和旧城拆合；旅游区必须把季节波动与生态承载纳入；重庆类
山地提高台地/桥隧权重，但不等于任意挖山许可。

### P7 全链验收

必须同时提供：

- 纯自然图，证明人类痕迹为零；
- 地形道路图，证明道路不是默认直线轴网；
- 旧城/新城/郊外切面，证明 epoch 与功能分布；
- 市场辐射密度图和缺口报告，证明使用真实网络时间与容量竞争；
- 同 seed 确定性、跨块连续性、入口可达、水体/岸线/保护区合规；
- 战略图、2.5D 近景和地面细节的运行态截图及 `visual-feedback.json`。
