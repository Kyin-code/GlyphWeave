# 核心城区自然生成与城市迭代设计

状态：**设计审核稿；用户后续已明确要求实现，V2 核心切片见 §14**

日期：2026-10-21

适用项目：GlyphWeave 现代世界生成；Rust Core 为唯一生成真源，HTML 只读取已烘焙结果。

## 0. 审核结论

上一版画面“逻辑大致成立但不像现代社会”，根因不是模型或颜色不足，而是生成顺序、
空间决策和需求表达仍混用了旧办法：

```text
先铺固定路网
→ 按 frontage 请求凑建筑
→ 用中心圆裁切城区
→ 用材质和高度区分新旧
```

本稿改为：

```text
纯自然世界
→ 山谷、渡口、山坳、泉眼、湖岸、海岬形成人类路径
→ 路径与资源点形成聚落候选
→ 根据城市规模选择核心切面
→ 旧核心、扩张、工业、新区、更新逐阶段演进
→ 容量与网络可达性决定建筑数量、用途和体量
→ 功能设施与生鲜市场按需求、容量和竞争布局
→ 工程改造、联合审计、完整烘焙和视觉验收
```

本稿的核心原则：

1. **先有自然，后有道路，再有聚落和建筑。**
2. **普通建筑数量是结果，不是任务完成数。**
3. **大都市生成核心切面，不冒充完整城市。**
4. **新老城来自同一旧骨架的保留、拆合和更新，不是两套模板拼接。**
5. **中心性是道路、历史、交通、就业和公共设施共同形成的网络场，不是地图圆心。**
6. **商业、学校、医院、教堂/寺社、市场和公园按功能需求出现，不要求每个片区都有。**
7. **局部硬合同不因城市等级放宽；填海、开山、台地和隧道作为独立宏观工程记账。**
8. **本轮先审核设计，不继续扩大实现范围。**

## 1. 对 48 城样本的调查口径

### 1.1 调查对象是核心切面，不是整城平均

参考对象仍是中国 12、美国 12、欧洲 12、日本 6、香港 6，共 48 个案例。
已经落盘的资料：

- `assets/data/urban-case-priors-48.json`：48 条机器可读索引；
- `docs/collaboration/b04-case-register.zh-CN.md`：案例、地形、形态与资料等级；
- `docs/20260906-human-settlement-morphology-research.zh-CN.md`：区域形态研究；
- `docs/modern-mainland-morphology.zh-CN.md`：地块、密度、设施与城乡参数；
- `scripts/check-urban-case-priors.mjs`：48/48 数量、地区分布、ID 和字段校验。

这些资料目前主要证明“应生成什么机制”，还没有全部转成可烘焙的核心区数值合同。
后续参数化必须遵守：

- 不用全市人口密度、全市路网密度、全市绿化率直接铺进 1km 地图；
- 每个案例只取可解释的核心窗口，例如“老城—河岸—新区”“站城—住宅—商业带”；
- 每个数值必须注明来源、日期、窗口、单位和 `inferred/heuristic` 状态；
- 无可靠公开数值时使用案例机制和明确标记的启发式先验，不伪造精度。

### 1.2 跨 48 城可复用的空间规律

| 规律 | 对生成器的要求 |
|---|---|
| 自然条件先决定聚落位置 | 山谷、渡口、泉眼、港湾、山坳、农牧交错带先形成节点 |
| 道路先连接资源和节点 | 主路沿谷地/等高线，支路围绕已有地块生长，平地才允许规划网格 |
| 老城通常继承细骨架 | 保留旧路、小地块、混合底商、广场、市场、寺社/教堂和市政节点 |
| 新区通常交通先行 | 站点、快速路、港口或产业园先落地，再形成大街区、办公、住宅和大型商业 |
| 城市边缘不是“低密度城区” | 郊区、旅游、放牧、种植、保护地分别有道路、地块、设施和季节逻辑 |
| 商业是多层级网络 | 底商、便利店、社区菜场、邻里超市、大型超市、批发市场和周期市场并存 |
| 更新是旧结构的再解释 | 留、改、拆、合、填充都有父对象和阶段账本，不能只换外观 |

### 1.3 区域类型学只作为先验

| 类型 | 旧城/更新常见结构 | 新区/边缘常见结构 | 商业与公共服务 | 主要工程压力 |
|---|---|---|---|---|
| 中国 | 胡同/里弄/骑楼、大院、城中村、单位与超大街区并存 | 轨道新区、产业园、封闭小区、填海/山前新城 | 菜场、底商、社区商业、区域商场、批发市场 | 旧城拆合、轨道、填海、台地、挡墙 |
| 美国 | 老网格、商业走廊、公寓与独立住宅混合、滨水再开发 | 细分住宅区、商业带、停车广场、公交导向填充 | 邻里食品店、超市广场、农贸市集 | 高速更新、低洼排水、滨水再开发 |
| 欧洲 | 连续街墙、庭院街区、小广场、历史核心、公共住房 | 绿带、轨道新城、旧工业/港口更新 | 市场厅、街区商业、电车/轨道节点 | 历史保护、旧港更新、防洪 |
| 日本 | 细地块、町家、商店街、轨道站与寺院并存 | 团地、站城开发、填海与防灾更新 | 商店街、站前商业、社区市场、寺社节点 | 震后重建、陡坡、窄路防灾 |
| 香港 | 高密混合街区、唐楼、屋邨、垂直混合 | 填海、新市镇、轨道上盖、旧工业更新 | 街市、屋邨商业、地铁/天桥商业 | 填海、陡坡、挡墙、高密度管线 |

这些类型不是国家硬模板。同一个世界可以组合“欧洲庭院旧城 + 美国式郊区边缘”或
“中国封闭社区 + 香港式站城商业”；最终结果由地形、历史、路网和需求决定。

## 2. 纯自然阶段 N0

### 2.1 输出

在任何道路、田地、建筑、围栏和市场出现前，冻结一套自然世界快照：

- 构造地貌、山脊、谷地、盆地、台地、坡向、曲率；
- 流域、分水岭、河流、湖泊、湿地、海岸、潮差、水位和流向；
- 土壤类型、含水、肥力、盐碱、侵蚀和承载力；
- 气候带、季风、主导风、降水、温度、洪水/滑坡/风暴等灾害；
- 生态群落、林木线、草地、灌丛、湿地植物、岩石和动物栖息地接口；
- 自然资源和可建设地评分，但此时不存在“城区”“农田”等人工用途。

### 2.2 必须表达的细节

- 草场、林地、灌丛和湿地是连续群落，不能以同心圆、棋盘格或固定半径随机斑块出现；
- 植被由海拔、坡度、坡向、土壤湿度、盐度、洪泛频率、风和演替阶段共同控制；
- 河流弯曲、河漫滩、阶地、冲积扇、冲沟和湖岸浅滩具有连续关系；
- 水面使用独立水位与岸线模型，不能把低洼地表直接染成水；
- 自然阶段允许高草、枯木、裸岩、泥滩和季节状态，但没有任何人类构筑。

### 2.3 闸门

- `humanTraceCount = 0`；
- 陆地实体不得进入水体，岸生植物必须使用明确岸线规则；
- 1m 高度、材质、岸线和 chunk 边界连续；
- 同 seed 重烘焙快照一致；
- 战略图和自然近景中看不到道路、建筑、农田、围栏或人工铺装。

## 3. 人类路径阶段 H1

### 3.1 候选节点

从自然快照中寻找：

- 河谷较缓段、山坳、泉水、湖岸浅湾、渡口、海岬、港湾；
- 山脊通道、林木线边缘、可耕冲积扇、牧草地入口、矿产或特殊资源点；
- 天然跨河点、避风处、洪水线以上台地、视野和防御位置。

节点只是候选，不保证成为聚落。处于陡坡、洪泛区、无稳定水源、无接入成本过高
或生态敏感区的地点应具名拒绝。

### 3.2 道路搜索

路径不是把两点连线后加噪声，而是在地形成本场上搜索并平滑：

```text
travelCost =
  slope + verticalWork + curvature + wetness + floodRisk
  + forestPenalty + soilCost + waterCrossingCost
  + protectedAreaPenalty + constructionCost
```

道路类型至少区分：

| 类型 | 生成逻辑 |
|---|---|
| regional | 连接渡口、港湾、城镇和主要资源，允许桥隧/堤道 |
| arterial | 连接城市核心与新区/产业区，优先避开陡坡和保护区 |
| collector | 连接片区、站点、市场和公共服务节点 |
| local | 围绕已有地块和步行联系生长，服从街道界面和入口 |
| alley/path | 旧城、村落、田间、牧道和旅游步道，可窄且不规则 |
| farm/pasture road | 服务田块、棚圈、饮水点和集散地，不承担城市通勤 |

### 3.3 道路验收

- 道路长度/直线距离比和被地形抬升的绕行量可审计；
- 最大纵坡、横坡、填方、挖方、桥涵和挡墙均有合同；
- 过水必须形成桥、堤道、涵洞或明确拒绝，不能把道路画过水面；
- 同一道路跨 chunk 连续；
- 平地城市可以出现规划网格，但网格必须来自既有交通轴和平面约束，不能成为全局默认。

## 4. 聚落涌现与建设阶段

### 4.1 聚落候选评分

聚落不预设“必须有 N 个”。候选评分包括：

- 水源可靠性、水质、洪水频率；
- 可建地面积、坡度、排水和地基条件；
- 与既有路径、渡口、港湾、站场和资源点的接入；
- 可耕地、牧场、木材、渔获和矿产；
- 与已有聚落的互补性与竞争；
- 风景、防御、气候庇护和文化/政治意图。

结果为 0 个聚落是合法结果。每个未接受候选必须记录原因。

### 4.2 普通建筑数量改为需求结果

默认生产路径不再接受“必须完成 N 栋建筑”作为普通建筑输入。新的需求合同使用：

```json
{
  "developmentDemand": {
    "version": 1,
    "householdsTarget": 1800,
    "jobsTarget": 900,
    "retailFloorAreaM2": 24000,
    "serviceCapacityTargets": {
      "schoolPlaces": 1200,
      "clinicVisitsPerDay": 800,
      "marketStalls": 260
    },
    "countIsHardMaximum": false
  }
}
```

生成过程：

```text
住户/就业/商业/服务需求
→ 分阶段用途和强度预算
→ 地块可建面积、退界、入口、消防、地形和日照容量
→ 建筑类型、体量、楼层与占地
→ 实际建筑数量
→ unmetDemand 或剩余地块供给
```

固定数量只允许用于经审核的地标、市政必需设施或测试夹具，并必须在报告中登记
`explicitRequirement = true`。普通请求不得通过复制建筑、缩小合同或放宽入口来凑数。

### 4.3 阶段账本

| 阶段 | 主要新增 | 典型空间结果 |
|---|---|---|
| founding | 渡口、路口、泉边、寺社/教堂、早期市场 | 少量混合小地块，贴近自然节点 |
| old-core | 主街、市政、市场、工坊、连续街墙 | 细街网、小地块、高混合、旧建筑保留 |
| expansion | 铁路/公路、学校、住宅组团、仓储 | 沿交通廊道扩张，旧路继续存在 |
| industrial | 工厂、码头、铁路支线、工人住区 | 大地块与仓储，防护/缓冲带 |
| modern-new | 轨道站、快速路、办公、商场、公园、塔楼 | 大街区、交通先导、公共空间先行 |
| renewal | 保留、改造、拆合、填充和功能替换 | 旧骨架叠加新体量，不整片抹除 |

每个最终对象至少保存：

- `constructionCohort`；
- `parentId` 或前身引用；
- `preserve/modify/demolish/new/replace` 操作；
- 地块边界的保留与合并记录；
- 被替代对象的用途、体量和位置；
- 更新前后入口、道路和公共空间关系。

## 5. 核心城区切面

### 5.1 大都市不生成“整城统计图”

`city`、`metropolis`、`megacity` 默认生成有主题的核心切面：

- 山—湖—旧城—新区；
- 江—岛—港—工业更新；
- 老城轴—更新带—轨道新区；
- 山麓—旅游区—居民生活区；
- 城市边缘—农田/牧场/保护地。

切面必须声明焦点、跨边界道路/河流/轨道、场外接入意图和不能在地图边缘伪造终点的
连接。小县城和村落才允许完整展开行政边界与外围生产空间。

### 5.2 中心性是网络场

禁止只写：

```text
到中心距离 < R → 商业
到中心距离 > R → 住宅
```

改为：

```text
centrality(x,z) =
  historicAnchor
  + roadBetweenness
  + transitAccess
  + jobAccess
  + civic/commercialAccess
  - terrainBarrier
  - protectedBarrier
```

不同中心可以重叠：老市场、寺社/教堂、市政广场、铁路站、港口、大学、医院和新区商场
都可能形成次中心。距离使用道路网络时间，不使用穿过水体和围墙的直线距离。

商业布局应同时受中心性、临街面、租金代理、住宅/就业需求、停车/公交和竞争影响。
因此商业从中心向外通常衰减，但会沿商业街、站点和旧市场形成枝状、带状和簇状分布，
不应呈现同心圆。

## 6. 功能片区

| 片区 | 空间骨架 | 主要功能 | 不应出现的行为 |
|---|---|---|---|
| 旧核心 | 旧路、小地块、连续街墙、市场/寺社/教堂/市政 | 混合住宅、底商、社区服务、历史公共空间 | 整片推平后铺新区塔楼 |
| 更新带 | 保留街块 + 合并地块 + 新公共空间 | 公寓、办公、社区商业、学校、诊所 | 只换材质冒充城市更新 |
| 新城区 | 站点/快速路/滨水公共空间先行，地块尺度较大 | 写字楼、塔楼、商场、医院、公园、住宅组团 | 每个地块强制一栋楼 |
| 郊区 | 公交/车行走廊、住宅组团、商业带 | 独立/多户住宅、超市、学校、体育、产业园 | 全市统一高层或农村式空地 |
| 旅游区 | 景观入口、步行环、码头、住宿组团 | 餐饮、纪念商业、周期市场、旅馆、交通换乘 | 常住人口需求被游客需求完全替代 |
| 放牧区 | 草地、牧道、围栏、饮水点、棚圈 | 牧业、饲料、兽医、集散设施 | 用城市道路和住宅填满牧场 |
| 种植区 | 田块、灌渠、田埂、农路、仓房 | 粮食/经济作物、集散、农资和村庄服务 | 无水源地画整齐棋盘农田 |
| 保护区 | 连续自然界面、有限步道和入口设施 | 生态保护、科研、低强度游览 | 城市商业与住宅无边界蔓延 |

### 6.1 建筑与设施规则

- 写字楼：高地价/高网络中心性、轨道或干道可达、地块容量足够；不按城市几何中心机械放置；
- 住宅：受就业、学校、市场、噪声、污染、坡度和日照影响；同一片区允许多种住宅；
- 商超：按人口/就业/游客需求和配送条件选址，区分便利店、邻里超市和大型超市；
- 教堂/寺社：由文化背景、历史 cohort、社区规模和公共节点决定，不是每个城区必有；
- 学校、诊所、消防、公园：按服务容量和网络时间落位，并与地标明确区分；
- 工业/仓储：靠近港口、铁路、快速路和城市边缘，保留安全与环境缓冲；
- 码头、站场、机场、填海和大型桥隧：作为一等宏观设施，不混入普通地块填数。

## 7. 生鲜市场与辐射密度

### 7.1 设施层级

| 类型 | 服务对象 | 容量表达 | 典型位置 |
|---|---|---|---|
| 社区菜场/湿货市场 | 日常生鲜、固定居民 | 摊位面积、冷藏、日客流 | 旧核心、密集住宅街区 |
| 便利店生鲜柜 | 小批量、即时需求 | 冷藏面积、营业时段 | 站点、街角、社区入口 |
| 邻里超市 | 综合日常采购 | 营业面积、停车/卸货 | 普通城区、站城混合区 |
| 大型超市 | 家庭批量、驾车/公交 | 建筑面积、停车、配送 | 新区、郊区走廊 |
| 周期市场 | 农户、游客、节庆 | 摊位容量、开放周期 | 广场、旅游入口、乡镇 |
| 批发/集散市场 | 农户、餐饮、物流 | 日吞吐、冷链、装卸 | 城市边缘、铁路/港口 |

### 7.2 辐射模型

对需求点 `i` 和设施 `j`：

```text
A_ij = capacity_j * quality_j * exp(-beta_mode * travel_time_ij)
P_ij = A_ij / sum_k(A_ik)
L_j  = sum_i(demand_i * P_ij)
rho_i = sum_j(capacity_j * exp(-beta_mode * travel_time_ij))
deficit_i = max(0, demand_i - rho_i)
```

- `travel_time_ij` 来自真实步行、道路、公交或车行网络；
- 步行、骑行、公交和驾车使用不同衰减系数；
- 同一市场有负载上限，过载进入候选扩展或扩容；
- 竞争由分母自然形成，不按统一半径去重；
- 居民、就业、游客、季节人口和农牧人口使用不同需求权重；
- 输出不是“附近有没有市场”，而是容量、负载、时间带、局部供给密度和缺口。

### 7.3 机器可读输出

- `market-program.json`：设施层级、容量、服务和选址候选；
- `market-catchment-field.json`：每个需求点到设施的分摊和实际网络时间；
- `market-radiation.json`：5/10/15/30 分钟供应密度、竞争和负载；
- `market-deficit.json`：未覆盖需求、原因、建议新增容量；
- `market-radiation.png/svg`：审计辅助图，不作为视觉验收替代品。

## 8. 自然改造与城市工程系数

### 8.1 两层工程

第一层是局部硬合同：

- 建筑 pad 有界削填、入口净空、步道坡度；
- 道路最大纵坡、填方、横坡、岸线净距；
- 水体、保护区、洪泛区和历史保护对象禁改；
- 建筑、道路和生态 footprint 的碰撞与接地。

第二层是宏观工程：

- 路堤、高架、桥、隧道、台地、海堤、填海、开山、河道治理；
- 每项操作必须记录 footprint、体积、来源、目标标高、排水、灾害、生态影响、预算和审计；
- 宏观项目可以改变自然快照，但不能静默放宽第一层合同。

### 8.2 城市规模和地形系数

建议使用连续场，不直接给城市贴一个“工程倍率”：

```text
engineeringPressure(x,z) =
  settlementScale
  * regionalDevelopmentDemand
  * networkCentrality
  * terrainScarcity
  * protectionResistance
  * specialRegime
```

- 平原城市：填方/道路成本低，土地供给较宽，更倾向水平扩张；
- 山谷城市：台地、挡墙、桥隧、盘山路权重高，不自动获得无限开山权；
- 海湾/岛屿城市：填海和海堤可成为候选，但必须有岸线、潮汐、生态和防洪审计；
- 旧城更新：拆合和地下空间权重高，但历史对象和街道界面受保护；
- 旅游区：季节容量、景观视廊和生态承载先于建筑覆盖率；
- 放牧/种植区：水源、土壤、运输和田块/牧道决定工程，不能用城市系数覆盖。

## 11. 验收场景

### 11.1 必做样例

| 样例 | 目的 | 必须看到的差异 |
|---|---|---|
| 山湖谷地 1km | 自然—山坳—湖岸—旧镇—新区 | 道路沿谷/绕坡；旧城细骨架；新区交通先行 |
| 江海核心 1km | 老城—河道—港区更新 | 老城连续界面、码头/仓储、跨河桥涵 |
| 平原县城 1km | 完整聚落 + 外围农田 | 田块由水渠/土壤决定；中心商业和社区市场分层 |
| 海岸旅游 512m | 渔村/旅游/保护地 | 居民与游客需求分离；季节容量；生态边界 |
| 农牧边缘 512m | 牧场/种植/村庄服务 | 牧道、围栏、饮水点、农路、集散设施 |
| 同 seed 类型对照 | 中国封闭社区 vs 美国郊区 | 地块、FAR、住宅面积、停车和街道结构不同，而非只换颜色 |

### 11.2 每个场景的统一验收

- 自然阶段人类痕迹为 0；
- 道路不是两点直线，弯道和纵坡能回到地形成本；
- 建筑数量随需求和容量变化，不能从请求 `count` 直接复制；
- 同一地块可保留、修改、拆合或替换，并追溯到父对象；
- 旧城与新区在街网、地块尺度、体量、用途和公共空间上可解释；
- 商业布局由中心性/临街面/竞争形成，不是单一圆环；
- 生鲜市场有容量、网络时间、负载、覆盖和缺口；
- 农田、牧场、旅游和保护地各有独立设施逻辑；
- 填海、开山、台地、桥隧和防洪全部进入工程账本；
- chunk 边界、道路、水系、岸线和实体 footprint 连续；
- HTML 中无大片白色空洞、明显空置、错接、悬空、落水或黑块；
- 视觉截图和 `visual-feedback.json` 与机器报告一致。

## 12. 审核拍板项

请审核以下选择：

1. **主链**：是否批准“纯自然 → 地形路径 → 聚落候选 → 核心切面 → epoch → 功能/市场 → 工程/烘焙”。
   建议：批准。
2. **建筑数量**：普通建筑是否彻底取消固定完成数，只保留需求、容量、结果和未满足账本。
   建议：批准。
3. **城市表达**：大都市是否默认只生成有主题的核心切面，不声称完整城市。
   建议：批准。
4. **新老城**：是否接受同一骨架逐阶段保留、拆合和更新，而不是两套并排模板。
   建议：批准。
5. **中心性**：是否用道路/交通/历史/就业/公共设施的网络场取代硬同心圆。
   建议：批准。
6. **市场**：是否以容量、真实网络时间、竞争和需求缺口作为市场布局与辐射密度依据。
   建议：批准。
7. **48 城使用方式**：是否以 48 个核心切面作为参数先验，全部进入案例表，但只选择代表性样例做完整烘焙对照。
   建议：批准。
8. **工程权限**：是否坚持局部硬合同不放松，填海/开山/台地等只通过显式宏观工程和城市系数管理。
   建议：批准。

审核通过前，本稿不继续扩展普通城区生成；已有 P0–P7 控制场景保留为技术证据，

## 14. 2026-10-21 生成链 V2 补充

本节把后续补充要求按生成链类型并入审核稿，并记录已经落地的核心模块。

### 14.1 自然地理不再是一句话

`naturalGeography` 支持两种模式：

1. `authored`：作者或 Agent 写明构造、气候、水文、地貌和灾害；
2. `derived`：Manifest 只写 `setting`、区域起伏、气候带和派生 seed，
   Rust Core 确定性展开其余内容。

`derived` 会生成：

- 构造抬升/沉降；
- 主导风向和雨影；
- 排水格局、河流密度、弯曲度和河漫滩；
- 历史河道改道；
- 海岸波候、潮差和侵蚀；
- 风蚀/风积、冰川、喀斯特和滑坡；
- 灾害和证据字段。

这些不是只写报告：河道密度改变下切间距，弯曲度改变河道场，雨影降低背风
湿度，沉积、侵蚀、冰川槽、喀斯特与滑坡改变高度场。纯自然实烘已通过
`humanTraceCount=0`、scale audit 和 quality report。

### 14.2 48 城改为“完整核心切面先验”

48 城 JSON 已升级为 v2。每案必须包含：

- 自然地理及地貌过程；
- 至少三段历史轴；
- 旧核心、更新、新区、边缘结构；
- 中心体系；
- 社区类型；
- 特殊因子；
- 土地压力先验；
- 证据等级。

校验覆盖 48/48、区域分布、历史顺序、过程合法性、压力范围和字段完整性。
Rust Core 已可直接读取同一数据，并输出自然草图、urban slice 和压力配置。

### 14.3 大都市切面必须有表达对象

`urbanSlice.semanticsVersion = 2` 新增：

- `viewpoint`；
- `focusRelations`；
- `requiredAnchors`；
- `contextAnchors`；
- `edgeIntents`。

语义 v2 的 feature-cut 必须解释：

```text
谁
与什么地理对象
发生什么关系
哪些主体锚点必须出现
边界外连接来自/去往哪里
```

因此“西湖、白宫、深圳湾”不是只作为名称或背景色，而是形成必须满足的空间
关系。旧 Manifest 继续按 v1 兼容解释。

### 14.4 规划史与最终实体

新增 `planningHistory`：

- 以路线图网络计算中心性；
- 识别金融、政治、港口、旅游、历史和混合中心；
- 给出街面保留、再开发评估、连接填充和新增长建议；
- 生成道路拓宽动作；
- 按人口和就业生成公园面积需求。

道路计划已经转为有旋转角、有设计高程的最终道路实体；容量建筑已经转为有
尺寸、标高和入口的最终建筑实体。入口合同不通过的建筑必须进入具名报告，
不能静默删除。

### 14.5 土地压力和工程系数

压力不再只是距离中心远近：

```text
landPressureIndex =
  urbanScale
  * centrePressure
  * terrainScarcity
  * (1 + protectionResistance * 0.18)
  * specialRegime
  * tourismSeasonality
```

如果 `referenceData.caseIds` 命中 48 城样本，还会融合该案例的核心区压力
先验。网络中心性来自路线数量、锚点数量、网络长度和绕行程度。

工程强度：

```text
engineeringScale = clamp(0.45 + landPressureIndex * 0.90, 0.45, 2.40)
```

系数只改变宏观工程的候选、优先级和预算。以下局部合同不变：

- 道路最大填方 6m；
- 最大纵坡 8%；
- 最大步行坡 25%；
- 建筑 pad 最大削方 2m；
- 岸线净距、水体和保护区合同。

### 14.6 新的完整顺序

```text

→ Rust 派生自然过程

→ 地形路径

→ 功能/市场
→ 土地压力与宏观工程预算
→ 道路/建筑实体化
→ 入口与联合审计
→ 完整烘焙
```
