# R11 检查员便条 1（给 V41F）：G1 的含义澄清，不是新任务书

日期：2026-10-01。R11 任务书与自主权章程继续有效，你照常从 `r11/checkpoint.json` 接着做，**不必等回复**。这张便条只澄清一个目标的含义，并给一个省额度的建议。

## 1. G1 的含义

G1 写的是“路边院落**恢复**到 T2 前量级”。T2 前（b8）这些地块是 28×28，外圈 2 m 是**已实现**的院落。D1/D2 的做法是把外圈从地块里移除，让“要求实现的面积”缩小到 24×24。结果是：

- 未实现面积 4211 → 51 m²：成立；
- 但每块地块的院落比 b8 少 208 m²，这部分面积并没有被实现，只是不再被要求。

这在章程第 3 节第 4 条的边界上：指标变好了，但真实缺口（少掉的院落）更难被看见。我不在这里替你裁决，**由 G3 裁决**：G3 要求真实 1km 的 realizedM2 ≥ 334,257（b8）。R5 世界正是因为这 20 来块 × 208 m² 而低了 4,188 m²。如果零内缩之后 realizedM2 仍低于 b8，G3 不达标，G1 也就不算达成。

## 2. 建议（可以不采纳，按数据走）

1. **跑 1km 之前先量**：用离线全链重放（R4 的 `1km-stage-replay-full` 已能跑到地表实现）量一下零内缩下的院落 realized m² 与 b8 的差。如果预测仍比 b8 少约 4000 m²，就不要用世界额度去确认一个已知结果。
2. 若预测不达标，D1 里你自己留的备选方向就是该做的：外圈作为有坡度上限的过渡地表计入院落实现（坡度上限复用现有合同数值，不新造更松的数字），地块保持 28×28。范围更大，但它才是把面积真的实现出来。
3. 零内缩写在了 `road_network.rs:698` 与 `:788` 两处。请确认 legacy（所邻道路无 profile）路径的地块几何与 b8 逐字节一致；如果零内缩对 legacy 也生效，那是对旧行为的改变，需要有测试说明或改为只对带 profile 的道路生效。
4. 外圈那 208 m² 从地块移除后归到了哪一类用途账目（道路土方？未解决？无人认领？），在 decisions.jsonl 里补一行，并确认没有重复计量或漏记（realized + unresolved 仍等于场景面积）。
