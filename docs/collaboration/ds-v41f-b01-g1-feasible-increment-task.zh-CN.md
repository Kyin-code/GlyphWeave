## 2. 冻结条件与研究假设

来源：只读`bevy/work/collaboration/ds-b04-c1-r2-b02-w1/w1-collector-local.manifest.json`及其原35路/27节点/21义务。新试验用明确独立副本；正确来源声明和当前生产重建参与试算，不能以过期effective文档绕过新来源校验。

不改seed/origin/自然参数、zone、需求kind/count/id/尺寸/insets/setback、固定root毫米高程、既有道路/地块/入口、fill/坡度/保护合同，不删除21义务腾地方。

现有infer_end只给新增自由端点选**最小工程可行高程**；这对最小填方合理，但未证明对邻接地块供给最优。当前候选也只选择tier_for返回的一种宽度。因此在改全局carve前，先检验一个小假设：**在原工程包络内选择不同合法的新端点/授权道路宽度，是否能获得真实地块增量？**

这是假设，不预言必成功。不允许抬高fill上限、改变固定端点或任意改曲线使假设成立。

## 3. 先冻结一个小候选表，不扫完整网络

从已有S1/S2报告挑出工程通过但接近取得地块的走廊，排除一眼明显占用/水体/保护阻断。最多8个不同几何走廊，总设计状态最多24，先把表和选择依据写入本轮证据再执行。

每项列：start/end、是否既有节点、固定高程、授权purpose/tier/width、原最低profile结果、目标request/可用站点、原拒绝。

- 仅当end是**新增自由端点**时，才能从现有工程叶子允许范围选择另一个高程；固定节点只允许原值。
- 所选高度最多原infer_end结果+两个有明确来源的值（例如邻接parcel自然支撑高程或旧工程相容高程）；仍由生产design/verify验证全走廊，不从局部高度外推整路可行。
- 可以比较已授权12/16m；不得凭空发明tier。宽度/高程组合都算独立状态，总和24，不能分循环各24。
- 端点都是固定节点且无法合法变高时，如实说明，不浪费次数重复8000/7000/6000等已知违法固定端点扫描。
- 不更改stationSpacing/setback/建筑尺寸，不能通过缩房或改请求数取得增量。

无需全局搜索、零收益连接路递归搜索或新的优化库。

## 4. 试验执行与信用

可在现有模块内部`#[cfg(test)]`小harness复用私有生产叶子，候选状态隔离；不要为实验把AlignmentContext/ZoningMask全面pub，也不要复制一套放置/审核算法。

步骤：走廊生产design/append → 现有frontage测量 → 只对预测有增量者执行完整实现/审核。最多4个候选进入完整realize，累计总时限180s；其余低成本设计/候选计数全部记录。超时保留非权威诊断但不提交世界。

任何“成功增量”必须提供：
- 基线35条路/21义务身份和固定支撑/入口不变；
- 新地块真实entity/parcel/source request稳定ID；
- 原需求24仍在，按request ID新增realizedWithAccess>0；
- 新yard缺额0、旧4/9m²不增长；
- final使用声明来源的生产编码路径，道路审核pass、固定节点合同pass、access成立。

不把planned或profile可设计当实际实现。只到测量通过但realize拒绝时，记录第一次真实拒绝，不更新信用。

## 5. 本轮不改生产默认；结果决定下一步

该轮以受控小实验为交付，不改默认v3搜索/高度策略，不换全局carve合成。

- 若有正增量：输出最小见证、原候选/新候选同输入对照、必要设计改动提议。下一轮再将策略显式版本化接入生产，并逐步争取24；不在本轮顺手实现或烘焙正式图。
- 若无正增量：逐个给出失败阶段，明确本小候选集而非全局无解。尤其区分“真的工程冲突不能同时满足”与“当前组合/固定站点选择未覆盖合法方案”。不下结论说必须降低需求或必须全局max合成。
- 若所有有希望走廊都无自由端点/无合法替代高程，允许少于24状态停止；给最小后续设计选择，不强行耗尽预算。
