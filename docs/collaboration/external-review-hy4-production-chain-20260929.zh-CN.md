# HY4 外部审查：生产链盘点与最小真实切片建议

日期：2026-09-29。性质：**用户转交的外部审查意见归档与内部裁定**。

本文件记录 HY4 对 GlyphWeave 当前实现状态、真实生成链路和后续切片选择的建议。内容来自用户转交的完整意见，经过结构化整理；不代表 HY4 的判断已经由本项目独立复测，也不代表所有建议获得实现授权。

## 1. HY4 的核心要求

HY4 建议下一步不要重构全部系统，而是分三步：

1. 先盘点当前能力，不重构；
2. 选择一个最小真实业务切片并产生真实增量；
3. 再决定哪些未来接口现在必须预留，哪些实现过早。

每一项能力都应说明：当前能做什么、验证到什么程度、依赖、未覆盖场景、扩展需要和最大不确定性。能力状态必须分开记录：

- 生产可用；
- 已接模块但输入受限；
- 仅 fixture；
- 已有接口但未闭环；
- 只有设计；
- 尚未开始；
- 状态未知。

HY4 特别提醒：

- 能配置不等于能生成；
- 能生成几何不等于有真实语义；
- 能显示对象不等于关系正确；
- 测试通过不等于生产输入通过；
- 小区域烘焙不等于完整世界链路可用；
- 有稳定 ID 不等于 revision、关系和影响范围稳定；
- 能渲染不等于能审核；
- 能审核一次不等于能局部修改和回滚。

## 2. 建议核对的真实生产链

```text
输入
→ 解析
→ 环境与规则
→ 地形/水文
→ 道路
→ 地块
→ 建筑/设施
→ 入口/通路
→ 工程结构
→ 用途与地表
→ 来源与账本
→ 审核
→ 保存
→ 消费
```

HY4 要求区分：

- 同一真实链路中的模块；
- 仍需手工中间文件的模块；
- 只在 fixture 或局部预览中使用的模块；
- 已进入权威世界模型的结果；
- 只存在于渲染/临时表达层的结果；
- 消费者是否可能绕过 Rust 真源补造信息。

## 3. HY4 对当前业务切片的建议

建议建立一个完整的代表性 512m 世界，包含：

- 明确环境背景；
- 真实地形约束；
- 道路等级与可达性；
- 地块边界与用途；
- 建筑类型、体量和入口；
- 院落或公共空间；
- 农田、自然保留地或保护边界中的至少一种；
- 用途、覆盖和所有权账本；
- 稳定 ID 与来源；
- 独立审核；
- 至少一个完整消费者。

当前 512m 世界运行额度已经用尽，因此该建议不能被立即执行，也不能用旧世界冒充新代码验证。当前可执行的最小前置切片是：

```text
base RoadEdge
→ authoritative RoadProfile
→ RoadNetworkPlan::entities()
→ frontage::stations()
→ candidate site
```

待 T3 离线闸门通过后，使用已保留的最后一次 1km 额度验证真实生产增量；未来获得新额度后，再把代表性 512m 世界固化为黄金场景。

## 4. HY4 建议优先冻结的接口

### 4.1 道路语义

道路不应只有最终几何，还应逐步表达：

- 道路等级；
- 通行权限；
- 单向/双向；
- 交叉口与连接关系；
- 桥梁/隧道/平面道路类别；
- 坡度和高程；
- 服务设施端口；
- 行人可达关系。

当前最紧急的不是一次性补齐所有交通语义，而是先闭合基础道路 profile—frontage 链。

### 4.2 规划与实际

重要对象应区分：

```text
planned
realized
unresolved
conflict
excluded
```

至少覆盖道路、地块、建筑、设施、用途、地表和工程结构。缺额必须说明原因：算法失败、输入不足、规则冲突、资源限制或人工确认。

### 4.3 影响范围

局部编辑的用户选区不等于实际影响范围。未来 Patch 应返回：

- 用户意图范围；
- 直接修改对象；
- 依赖对象；
- 传播影响区；
- 需重建的 chunk；
- 需重新审核的对象；
- 可回滚的旧 revision。

### 4.4 来源与环境参数

环境参数建议使用五态：

- `userProvided`；
- `importedObserved`；
- `derived`；
- `assumed`；
- `unknown`。

同时保存依据、来源、时间、适用尺度、影响对象、不确定性和是否可自动补全。低影响参数可显式假设；影响气候、地貌、重大用地或物理规律的参数必须进入确认项。

## 5. HY4 对 FUT-01 至 FUT-06 的建议

- **FUT-01**：先支持单栋建筑替换、小块地块重生成、局部地形微调；必须返回传播影响区，支持原子提交和完整回滚。
- **FUT-02**：新对象按“组合原语→受约束 Recipe/DSL→隔离生成器”分层；规则声明输入、输出、作用域、尺度、支撑、悬空、端口、冲突优先级、来源和版本。
- **FUT-03**：先定义公里级整体身份、走廊、功能、净空和端口，再分段生成；第一版只验证静态跨 chunk 连续设施。
- **FUT-04**：通过环境假设替换实验验证风场、湿度、季节等参数确实影响生态、水文或用途建议，而不是装饰字段。
- **FUT-05**：按只有地名、部分 GIS、充分 GIS 三种输入强度处理；观测不能被补全静默覆盖。
- **FUT-06**：区分 procedural、assisted、local edit 三种身份；LLM 模式保存已批准计划、Recipe、规则、假设、输入快照和 Patch，不以 seed 冒充完整重放身份。

## 6. 内部裁定

HY4 的意见与 K3 基本一致，但更强调当前实现者视角和真实链路。内部采用方式：

- 当前立即采用盘点方法、能力分层、planned/realized/unresolved/conflict/excluded、影响范围和来源字段原则；
- A/B/C 共同底座先冻结确定性、ID、坐标、来源、chunk、存储/性能、接缝、黄金回归和机器可核验证据；
- B 后续再做轻量需求、RegionRulePack、城乡过渡、AbsurdityRulePack、冲突策略、基础市政骨架和命名；
- C/C 后再做完整局部编辑、开放规则、复合设施、环境背景、GIS、动态访问、历史和复杂重放；
- 当前不因 HY4 扩大范围，不启动 FUT 实现，不改变 B01-R1 T2 的道路 profile 主线。

## 7. 必须保留的不确定性

以下不能仅凭文档或 fixture 判定，必须用固定输入的真实运行确认：

- 当前源码下完整 512m 世界的端到端链路；
- 当前源码下最后一次 1km profile 候选的真实 frontage 增量；
- 最大图下道路、地块、用途、账本和消费的一致性；
- 普通地形、道路、河流和实体跨 chunk 接缝；
- 环境来源字段是否真正影响生成结果；
- 局部 Patch 的依赖闭包和回滚是否真实工作。

这些状态不能用旧世界、配置项、测试数量、截图或局部预览替代。
