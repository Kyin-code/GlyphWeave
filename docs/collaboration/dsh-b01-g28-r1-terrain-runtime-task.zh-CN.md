## 3. 实施要求

### R1-1 修真实JS接口，不复制一套“正确数学”代测

- 统一indicesFor定义和全部调用，绘制和拾取消费同一索引拓扑。
- 维度必须为有效整数，顶点长度与维度一致；非法参数（特别surface对象误传宽度）显式拒绝，不悄然生成空索引。
- 地形draw路径必须要求有效非空索引，不能以空数组触发非索引drawArrays兜底。实体独立非索引三角路径可以保留，但要明确区分。
- 不伪造surfaceTriangleCount/drawnTriangleCount为模型声明值。计数应来自实际准备并提交的索引与实体几何；正常固定场景地形7938三角、23814索引、4096顶点，两面分别符合；实体/道路7个体块×12面=84时总提交8022（若去重绘制另有明确策略，必须据实际解释）。
- actual viewer JS可执行回归：64×64、2×2、非法维度/类型、非零/负原点、三角对角线、可见面与拾取一致。禁止只有Rust geom绿测试或字符串包含断言。
- 对实际render和surfacePickData调用链做至少一个集成断言，防止函数单独正确但调用仍错位；测试坏参数会失败，不改期望凑绿。

### R1-2 补用户交互与旧合同遗漏

- final/natural分别真实鼠标点击没有实体遮挡的地形三角，Selection显示surface/triangle/源样本及派生命中点，和state/独立数学oracle一致。
- 保留实体选择/清除正确性；背景清除必须从“已选实体”开始单独执行，不先按clear让状态预先为空；隐藏已选图层与拖拽不误选实际观察。
- 实际拖拽和滚轮验证，不只按旋转/缩放按钮；至少1280×800、960×640检查控件可达与面板不占满视口。
- 更正仍为path-A-fact-only的UI标签，明确真实3D只读消费者；保留来源和工程/路线未验证限制。

### R1-3 重做可信视觉与性能观察

- 先验证完整网格和地形命中再做视觉结论。修复后以同源、同视口、明确相机参数拍整体/俯视/近景三张新截图并实际查看。
- 至少一组地形单独显示（实体/道路/观测叠加关闭），证明不是实体像素或2D overlay在替代地形。两表面均需确认。
- 旧84三角/错误条带图只作失败对照，不用它的绿通道指标证明新地形已好看。若继续测像素指标，记录区域、遮罩、样本数、色域/通道和公式；绿通道均值比只能按该名称解释，不称通用亮度或无障碍对比度。
