# r49：农业人行路面查询索引与负标高站点修复

日期：2026-09-07。状态：实现/验证进行中；最大图及整个项目完成状态尚未证明。

## 1. 背景与不可改变的要求

r48 在原 6×10km、seed=7 场景中新增 120 栋住宅、24 间商铺需求，生成在 600 秒预算内未能发布完整世界。地表实现耗时 281.765 秒，之后独立重建仍未完成。本轮保持全部需求、场景、道路、田块/生态密度和质量门禁；不缩小输入、不删除实例、不取消独立重建、不提高原验收预算来制造通过。

深入检查 r48 中间文件还发现：道路 270/270 实现，但站点仅 250/300 通过变换审计。因此 r48 的 144 个已规划新建筑不能当作已正确实现建筑；先前 r48 文档没有完整世界可供核验，不构成最大图交付证据。

## 2. 两项修改必须分开归因

### A. 精确人行路面空间索引（应保持结果等价）

原农业单元检查在缓存未命中时，依次检查水、保留用途、实体、**全部人行三角形**，再计算全单元坡度。每栋建筑新增入口几何，线性扫描随入口三角形数量增长。该路径是当前明确可消除的重复工作；其对整图耗时的贡献须由实测确认，而不是仅凭代码推测。

新增 `G:\difyllmwiki\GlyphWeave\bevy\crates\core\src\settlement\pedestrian_index.rs`：

- 16m 空间桶只做候选筛选；不栅格化、合并、删除或降低原三角形精度。
- 保留原 triangle-vs-cell 的包围盒检查、绕序归一化、精确多边形裁剪及 `1e-8` 正面积阈值。
- 负坐标使用欧几里得除法；跨桶、边界接触和极薄三角形进入原精确判定，不靠中心点采样。
- 单三角形超过 4096 个桶时进入全局候选列表，避免为巨型三角形展开无限空间表，仍完整参与检查。
- 检查非法索引和非有限/超出世界整数坐标域的顶点并返回错误，不把非法数据忽略为无障碍。
- 农业的完整结果与独立重建均使用索引；原线性查询保留在测试中作为参考，不提供可绕过生产校验的运行参数。

索引不改变公共 manifest 或面积合同。新增只读 `glyphweave.landcover-trace`，在既有 `GLYPHWEAVE_BAKE_TRACE` 开启时分别记录访问图、院落、农业、自然覆盖面和生态阶段耗时；日志不进入权威世界数据。

### B. 负毫米标高的计划站点被旧自动抬升（修复错误结果）

r48 第一个失败站点位于 `(3788,4920)`，计划支撑为 **-1354mm**：worldY=-2，bottomOffsetM≈0.646。旧预烘焙自动贴地把 -1.354m 转为四分之一米，再对扣除偏移后的值 ceil，导致 worldY 变成 -1，整栋房屋和它的后续整地被抬高 1m。

新增真实坐标回归先复现失败。明确的 frontage 平台不再进入旧的整米/四分之一米自动贴地路径，也不能由后续 baked-surface rebase 或移动补救偷偷修正。存在真实不匹配时，仍交给来源重建、完整毫米支撑与入口审计报告失败，不能把改写源实体当作修复。

这项修复会改变 r48 的错误最终地形/变换；不能将本轮整体说成全部输出不变。**性能索引的等价对照必须在同一修正后地形、实体、计划和入口几何上进行**，把性能优化与正确性修复分开证明。

### 索引候选完整性的不变量

若三角形与整数单元 `[x,x+1]×[z,z+1]` 有正面积相交，则其包围盒满足 `minX < x+1`、`maxX > x`（Z 同理），所以 `floor(minX) <= x <= floor(maxX)`。对 16m 桶做同一欧几里得整除后，查询桶必在该三角形登记范围内；巨大范围进入全局列表也不会遗漏。桶边界多包含候选只增加精确检查，不改变接受结果。最终仍调用原裁剪谓词，且查询只返回布尔值，不依赖“第一个三角形”的身份或遍历顺序。

该不变量只覆盖已校验的有限世界坐标与整数单元查询，不意味着任意非法输入、真实三维体积或未来非整数单元也已被证明。测试与实际农业逐字节对照仍是交付要求。
